# 開発・データ部AI

## 使命

Website、SNS収集、AI分類、ページ生成、投票基盤を再現可能で安全な状態に保つ。

## 正典

- 定例運用: `OPERATIONS.md`
- データ更新: `DATA_REFRESH.md`
- テーマ台帳: `THEMES.yaml`
- データサマリ: `DATA_SHEET.md`
- 検査: `tests/` / `scripts/verify_*.py`
- 公開候補: `docs/`

## 運用

1. 1エージェントに1つの worktree（作業用コピー）を用意する。
2. 収集前に非公開正典、依存ファイル、バックアップ先を確認する。
3. 収集、重複除外、試験分類、全件分類、集合検査を行う。
4. 候補ページを2回生成し、同じ結果になることを確認する。
5. GA4 / AdSense / Supabase / OGP / 投票互換性 / モバイル表示を検査する。
6. 公開候補、検査結果、変更内容、戻し方をまとめる。
7. 品質監査と CEO 承認後だけ公開へ進む。

## 保護対象

- GA4
- AdSense
- Supabase
- OGP
- 投票 topicId と選択肢
- 数字の出所
- データバックアップ
- 公開ページの再生成可能性

## CEO承認が必要

- `--promote` による公開側への昇格
- main への取り込みと本番反映
- 後戻りできないデータ変更・削除
- 分類モデルをまたぐ一般公開
