# SNS反応まっぷ デザインシステム

現行サイト（https://sns-reaction-map.jp/）から抽出。
新規テーマ作成、バナー画像、インフォグラフィック、マンガ、OGP画像のプロンプトに使用する。

## 4. コンポーネント仕様

### ヘッダー（sticky）

```
背景: rgba(255,255,255,.92) + backdrop-filter: blur(16px)
下線: 1px solid rgba(222,230,241,.9)
```

- 左: ロゴマーク（6つの色付きドット + 2本の楕円リング）+ テキスト
- 中: ナビリンク（`12px, weight 800`）
- 右: Xアイコン + アウトラインボタン + プライマリボタン
- テーマページでは `html, body` の横方向制御に `overflow-x: clip` を使う。`hidden` は縦方向をスクロールコンテナ化して `position: sticky` を無効化するため使わない。

### ロゴマーク

6つの小円（11px）を時計回りに配置、2本の楕円リング（`±35deg`回転）で囲む。
色: Blue, Blue2(`#2786ff`), Orange, Green, Purple, Orange の6ドット。
白い3pxの`box-shadow`でドット間を区切る。

### ヒーロー（トップページ）

- 3列グリッド: コピー / スキャッタープロットCanvas / サイドパネル
- 背景: 白 + 薄いグリッド線（`rgba(20,99,255,.035)` 48px間隔）
- CTA: pill型ボタン（`border-radius: 999px`）、ブルーグラデーション + 大きなシャドウ
- Canvas: 4色のクラスターポイント + 接続線

### ヒーロー（テーマページ）

- ヒーロー画像を右半分にフェードマスク（`mask-image: linear-gradient(90deg, transparent 0, #000 26%)`）
- 左にコピー: パンくず → badge → H1 → question-line → 共通分析文 → 「まず結論」
- `topic-modern.css` 適用時: 白背景パネル + `border-radius: 20px`
- H1の画面表示はテーマ名のみ。「SNS反応まっぷ」は `topic-modern.js` で除去する
- 共通分析文:

```text
収集したSNS投稿のうち、分析対象となった意見{分析対象件数}件をAIが{論点数}つの論点に整理しました。世論調査ではなく、SNS反応サンプルの論点比較です。
```

- ヒーロー高:
  - デスクトップ: 555px（inner 553px）
  - 720px以下: 834px（inner 832px）
- テーマごとの文章量でヒーロー高を変えない。短い場合は画像側の余白として処理する
- 必須参照: `site-tokens.css?v=2`、`topic-modern.css?v=23`、`topic-modern.js?v=8`

### 論点インフォグラフィック

- `#explainer-section .explainer-grid` はパネル内幅いっぱいに表示し、テーマ固有の `max-width` を設定しない。
- 全画像は `1915 / 821` の比率、`width: 100%`、`height: auto`、`max-height: none`、`object-fit: contain` で統一する。
- 画像を拡大せずカード内で見せる場合も、上下左右を切り落とさない。特に文字・トークン名・数値が端にある画像で見切れを確認する。

### 「議論の中心」

- 見出し: 「議論の中心」
- 補足見出しは置かない
- 項目は1つだけとし、最も投稿が集まった論点を扱う
- 「最多論点」という分類用語を見出しにせず、テーマ固有の問いへ翻訳する
- `conclusion-count` → `strong` → `conclusion-detail` で、件数・問い・短い説明を表示する
- 左上と右下だけを描く非対称フォーカスフレームを使い、一般的な角丸カードにしない
- 枠と件数は初回だけ動かし、常時発光させない。動きを減らすOS設定では停止する
- 不透明な独自スコアより、論点名、件数、割合など説明可能な値を優先する

### 注目指標カード

- コンテナ: `.stats.insight-stats`
- カード: `.stat.insight-stat`
- 原則4枚。テーマ理解に不可欠な場合は追加可
- 「分析対象の意見」は必須
- 残りは、最も多い立場、意見の割れ方、最多論点、最も割れた論点、最も熱い論点、第三案、共通点、判断の核心、当事者の声、判断保留から選ぶ
- 旧来の「収集投稿・分類済み・意見投稿・最多論点」という工程件数の羅列は使わない
- tone:
  - `debate`: 対立・賛否比較
  - `topic`: 最多・高熱量の論点
  - `option`: 条件付き・第三案
  - `insight`: 一致点・核心
  - `voice`: 当事者の声

### 論点解説の見出し

- 共通形式: 「このテーマを読み解く、{論点数}つの論点」
- 「投票前に読む」「○つの争点」は使用しない
- 補足テキストはテーマに合わせて変更可

### スタンスバー（分類比率）

```css
display: flex; height: 21px; overflow: hidden; border-radius: 6px;
/* 各色のspan。% に応じた width。白文字で%表示 */
```

- 高さはコンテキストで変化: 21px（カード内）/ 5px（ランキング）/ 4px（トピックリスト）
- 色順: Blue → Orange → Green → Purple

### 投票カード（vote-image-card）

```
aspect-ratio: 1;
背景: 論点イメージ画像 (background-size: cover)
オーバーレイ: linear-gradient(180deg, rgba(30,27,75,.25), rgba(30,27,75,.72))
ラベル: 白文字, weight 900, 16px, text-shadow付き, 左下配置
ホバー: translateY(-4px) + シャドウ拡大
border-radius: 8px (topic-modern時: 13px)
```

### 投票2問目のヘッダー

- ラッパー: `.vote-step2-head`
- 質問文の下に共通補足「選ぶと結果を表示します」
- 「← 論点を選び直す」をデスクトップでは右側、720px以下では質問文の直下に配置
- ボタン高38px、白背景、pill型、共通のfocus-visibleリングを使用
- 「開票します」「アリーナに表示します」「マップに表示します」など、テーマ固有の結果表示文は使わない

### 投票2問目の回答ボタン

- コンテナ: `#vote-stance-btns`
- 回答: `.vote-stance-btn`
- デスクトップ: `auto-fit` の等幅グリッド（最小190px）、gap 12px
- 720px以下: 1列
- 共通仕様: PC高182px（モバイルは最小142pxで内容に応じて可変）、上辺5pxの立場色、角丸13px、padding 16px 15px 14px
- タイトル15px、説明12px、末尾の「選ぶ」pillをカード下端に揃える
- テーマ固有の選択肢数や内部HTMLが違っても、列幅・高さ・余白は `topic-modern.css` を正典とする

### 投票結果カード

- `topic-modern.js` がテーマ固有HTMLを共通構造へ整形
- 選択内容カード92px、操作列40px
- 操作ボタンは「𝕏 でシェア」「投票をやり直す」
- 未設定値や `undefined` を表示しない

### マンガカード（manga-page-card）

```
border-radius: 8px (topic-modern時: 13px)
画像: aspect-ratio 2/3, object-fit: cover
下にキャプション: 13px, weight 900
ホバー: translateY(-4px) + シャドウ拡大
クリック: モーダルで拡大表示
```

### 2Dスタンスマップ（Arena）

- ダーク背景: `#0f0e2e` + arena-bg.webp
- セクション内側: 最大720px
- Canvasラッパー: 最大640px、背景 `#0f0e2e`、角丸10px
- Canvas内部座標: 640 × 640。中心320px、内周68px、外周216px、ラベル半径248px、投票マーカー半径142px
- 内部順序: 題名 → 説明 → 盤面 → あなたの場所の説明 → 凡例・フィルター
- デスクトップの盤面開始位置: セクション上端から196px（題名領域42px、説明領域84px）
- セクション余白: デスクトップ `42px min(6vw, 72px)`、720px以下 `30px 16px`
- Canvas上の論点名・中心ラベルは白系で表示し、中心円もダーク背景にする
- 投票位置: `topic-modern.js` の `drawArenaUserMarker()` を使用し、白い外円・立場色の内円・パルス・「あなたはここ」バッジを表示
- 選択範囲: `drawArenaSectorHighlight()` を使用し、立場色の半透明面・4px枠・発光でセクター全体を強調
- 投票前: 盤面を8pxぼかして操作不能にし、640px盤面の中央に「まず投票してからアリーナを見よう」を表示
- 投票後: 共通スクリプトがロックを解除。「選び直す」後は再ロック
- 説明文: `投票した選択肢を「あなたはここ」マーカーで表示しています。`
- フィルターボタン: pill型、アクティブ時アクセント色
- AI著作権テーマを正典とし、テーマ固有CSSで白い盤面や660px以上へ戻さない

## 5. 画像アセット仕様

### ファイル命名規則

```
{slug}-hero.webp            # ヒーロー画像 (テーマページ背景)
{slug}-vote-{N}-{key}.webp  # 投票カード画像 (4枚, 正方形)
{slug}-manga-page-{N}.webp  # マンガページ (3–7枚, 2:3比率)
{slug}-manga-charsheet-{name}.webp  # キャラ設定シート
{slug}-infographic-{key}.webp       # インフォグラフィック
ogp/{slug}.png              # OGP画像 (1200×630推奨)
```

### ヒーロー画像

- 用途: テーマページのヒーロー背景
- サイズ: 幅1200px以上、横長
- テイスト: テーマに関連する象徴的なシーン。半透明（opacity 0.18）でグラデーション越しに表示されるため、コントラストが強い構図が望ましい

### 投票カード画像

- 4枚1セット（各スタンスに対応）
- aspect-ratio: 1:1（正方形）
- 暗いグラデーションオーバーレイの上に白文字ラベルが乗る前提
- テイスト: テーマの論点を象徴するイラスト or 写真

### マンガ

- 3–7ページ（テーマの論点数に応じて）
- aspect-ratio: 2:3（縦長）
- キャラ設定シートで外見・性格を固定し、全ページでキャラ一貫性を維持
- フキダシの日本語テキストは画像内に含める（AI画像生成で対応可能）

### インフォグラフィック

- 論点ごとの視覚的な解説図
- 4色パレットに沿った配色
- テキスト込みの完成画像

### OGP画像

- サイズ: 1200×630px
- デザイン: テーマ名 + ブランドロゴ + スタンスバーのビジュアル

## 7. 画像生成プロンプト共通指示

バナー・マンガ・インフォグラフィック・投票カードを外部AI画像生成ツール（GPTimage2等）で作る際の統一指示:

### 色指定

```
必ず以下のブランドカラーを使用:
- メインブルー: #075ef2（賛成）
- オレンジ: #ff5b2e（反対）
- グリーン: #36b8a3（条件付き）
- パープル: #9358e8（保留）
- ネイビー: #071a3d（テキスト・見出し）
- 背景: #f6f9fe（薄い青みのオフホワイト）
```

### フォント・テキスト

```
- 日本語テキストはNoto Sans JP相当のゴシック体
- 見出し: 太字（Black/900相当）、letter-spacing詰め
- 本文: Regular 400
```

### トーン&マナー

```
- クリーン・モダン・データ密度が高い印象
- フラットデザイン寄り（過度なグラデーション・光沢は避ける）
- 角丸は控えめ（8px–18px）
- 白背景 + 薄い青みのカード影
- 情報の階層を色と太さで表現（華美な装飾より構造の明確さ）
```

### マンガ特有

```
- キャラ設定シートを先に生成し、全コマでキャラの外見を統一
- フキダシ内の日本語テキストは画像に直接含める
- 背景は簡潔に（テーマの象徴的な場所・状況）
- 4色パレットをアクセントに使用
```
