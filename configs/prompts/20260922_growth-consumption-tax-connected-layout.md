# 課題77 — 消費税減税テーマの連動表示を実装する工程表

作成: 2026-09-22
状態: 実装計画。オーナーは会話内表示案を「とても良い」と評価し、消費税テーマへ落とし込むステップの作成を依頼した。
この記録の時点では本番コードを変更しておらず、公開の承認を受けた記録でもない。
対象: `consumption-tax-cut`。公開URL・論点ID・投票の保存先と選択肢の意味を維持する。

## 完成形と範囲

**既存の立場バーと質問 → 山なみ → 選んだ論点の理由・投稿・制度・資料**が一続きに動く。
年表・収集比較・投票・授業用資料・調査方法も、会話内表示案の配置を基準に整える。
PCでは意見と資料を左右に、スマホでは上下に並べる。色・書体は既存サイトのものへ合わせる。

- [内容と配置の接続表](../../quality/designs/2026-09-22-task77-consumption-tax-connected-layout.md)を内容上の基準とする。
- 見た目の参照は会話内の `consumption-tax-connected-layout.html`。会話内専用の操作・固定数値・仮の投票は公開版へ持ち込まない。
- 既存の質問は再利用する。新しい質問、分類のやり直し、新規収集、全テーマへの配置変更は今回の工程に含めない。
- 1〜5は一つの公開候補を完成させる内部工程。各段階でオーナーへの承認依頼を繰り返さず、完成版と検証結果をそろえて公開判断へ進む。

## 確認済みの実装上の事情

1. `scripts/build_consumption_tax_page.py` はページ全体の生成に加え、冒頭の立場バー、背景、資料照合、X投稿を再挿入する。
   現在の `verify()` には、立場バーが調査条件より前、潮目が資料照合より前、資料カード6件など、旧配置に依存する検査がある。
2. `scripts/refresh_planet_section.py` は山なみ区間を別に作り直す。`_inject_ctc_landing_images` が消費税の7枚の図解を補っている。
3. `scripts/refresh_adapters/consumption_tax.py` は候補を2回生成し、潮目を貼り直す。投票定義28通りと保護要素の維持も検査する。
   通常のページ生成だけでは潮目が取り除かれるため、公開用候補はこの経路との接続まで確認する必要がある。
4. 授業節・編集情報は `scripts/seo/apply_classroom_section.py` と `apply_theme_trust.py` がさらに適用する。
   引用と授業の内部リンクは `docs/topic-modern.js` の `#panel`・`#list`・`#issue-{id}` などに依存する。
5. `verify_builder_rebuildability.py` の消費税対象は現在 `build_consumption_tax_arena.py`（集計生成）。
   この既存検査だけでは、新しいページ全体の再生成を保証できない。今回の画面を通る検査を追加する。
6. `configs/planet/consumption-tax-cut.yaml` の投票順は公約→効果→対象範囲→財源→給付比較→事業者→その他。
   山の見た目の順序（公約→対象範囲→効果…）とは別。番号の取り違えは過去の投票の意味を変える。

## 工程1 — 内容・対応関係・残す機能を確定する

すること:
- 接続表を実装に使うIDの表にする。7論点、投稿14件、資料照合6件、資料のみの4項目、共通する心配2件を照合する。
- 集計・理由分類・資料判定・投稿日/確認日・図解・投稿URLの読み取り元を固定する。会話内ファイルからのコピーを正典にしない。
- バーの件数と山は選択した立場に連動。理由分類・投稿例・資料は論点全体であることを画面に明記する。
- 資料照合がない論点と、理由の再読が未実施の論点を区別する。掲載した2投稿そのものを資料で判定したように見せない。
- 古い定型文を整理する。Q1の「差はわずか」は実数の差へ、Q2は件数でなく「強い表現の割合」へ。
  末尾に残る初期集計値は、現在値へ同期するか、初期調査の記録として日付・母数を明示する。
- 制度説明の9/19と資料照合の8/19を区別する。事実確認日を見た目の変更日だけで進めない。
- 現行の公開ページ・図解・主要リンク・投票定義・計測項目を比較用に保存する。

完了条件: どの論点にも出所と表示先があり、確認されていない内容を補っていない。残す機能の一覧がそろう。

## 工程2 — 通常のデータ更新で維持できる土台を作る

すること:
- 専用の作業ツリーで、必要な非公開正典・ペルソナを復元し、現行ページの再生成と既存検査を先に通す。
  不足ファイルと既存不具合は、新しい変更による不具合と分けて記録する。今回の計画書作成では非公開データの復元は不要。
- 消費税に限定した表示処理とCSSを用意する。推奨は、生成済みの本文・公開集計を使って操作を加える方式。
  JavaScriptが動かない場合も、7論点・資料・投稿リンクが本文として読める形を残す。
- 全体の立場と選択中の論点を一か所で管理し、バー・山・論点本文へ同じ選択を伝える。
  投票の選択、クイズの回答、収集比較の表示は別の状態として持つ。
- ページ生成、山なみ部分更新、資料だけの更新、昇格後の数値同期、授業節・編集情報の適用から、同じ表示に戻れるよう配線する。
  配置を直す処理を複数箇所に複製せず、消費税用の共通処理へ集約する。
- 論点や主張の対応はIDを使う。件数・表示順・ラベルの一致で結び付けない。
- 旧配置の検査は「情報の所在・件数・到達可能性」を守る検査へ変更する。失敗する検査を外して済ませない。

完了条件: 消費税の候補を同じ入力で2回生成して同じ結果になる。生成器に新しい処理が登録され、他テーマの表示が変わらない。

## 工程3 — 3論点で中心の体験を作り、7論点へ広げる

最初の3論点は、表示内容が異なる次の組合せにする。

| 論点 | この論点で確かめること |
|---|---|
| 対象範囲 | 再読理由7分類、投稿2件、制度設計、資料照合1件を一続きに読む |
| 財源と社会保障 | 再読未実施でも誤解なく表示し、資料照合3件を読み分ける |
| 事業者の実務負担 | 投稿と資料照合に加え、3つの措置と共通の心配をつなぐ |

- 立場を押すとバーが強調され、山の件数・幅・高さが約0.5秒で変化する。連打しても最後の選択に収束させる。
- 論点を押すと関連情報が同じ領域に入れ替わる。毎回画面を大きく飛ばさない。
- 既存の予想2問は対応する数字と山を示す。答えなくても先へ読める。
- 初期表示は試作を基準に「すべての意見＋対象範囲」。論点の固定リンクで来た場合は、その論点を優先する。
- 残る4論点へ展開し、資料0件・理由未再読・立場の件数0件でも、空白や不正な割合を出さない。
- 大きな図解は選択中の論点からその場で拡大できる。原画像は現行の7枚を使う。
- X投稿は現行の選定を維持する。選択中の投稿の表示と元投稿へのリンクをそろえ、埋め込みが失敗しても読める入口を残す。

完了条件: 7論点×5表示（すべて＋4立場）で、選択・数値・関連内容が一致する。確認用の数値は最新の入力から算出する。

## 工程4 — ページ全体と既存の利用機能をつなぐ

- 年表3段階を選べる形にする。過去の日付へ現在の制度説明を流用しない。
- 収集比較は更新回データから作る。試作の8/24・9/17や510・532を固定値にしない。
- クイズ6問は資料欄と共通のデータを使い、問題から対応する論点へ進める。
- 既存の進捗表示は「見た論点・質問・資料の数」という意味を維持する。再描画や立場切替で二重加算しない。
- 投票は既存の `vote-store.js` と28通りの保存番号を維持。表示順から保存番号を作らず、IDから固定番号へ変換する。
  閲覧中の立場を投票扱いにせず、投票操作は独立させる。
- `#issue-{id}` と `#{id}`、授業節からの移動、引用文・URL、ブラウザの戻る/進むを同じ論点選択へつなぐ。
- 授業用の理由3+3、資料3、問い3、印刷を維持する。印刷時には必要な本文が選択状態に関係なく出るようにする。
- 調査条件・編集情報・訂正窓口・関連テーマ・詳しいデータ・GA4・AdSense・canonical・OGPを維持する。
- 既存の `cite_copy`・`classroom_link_click`・`classroom_print` を継続。必要な追加は論点表示と出典操作の計測に絞り、
  再描画で重複送信せず、閲覧者が選んだ政治的な立場や自由記述を計測へ送らない。

完了条件: 実際の公開用データ・図解・投稿・既存機能で一巡できる、消費税ページ全体の候補ができる。

## 工程5 — 表示・既存機能・次回更新の3方向から検証する

| 検証 | 合格の形 |
|---|---|
| 内容と数字 | 意見総数・立場・論点の和と出所が一致。確認日と資料対応も一致する |
| 実機 | 320/375px・PC幅で、長い出典も切れない。表示の重なり、操作後の焦点消失、コンソールエラーがない |
| 操作 | キーボード、連続切替、端末の動きを減らす設定、論点リンク、戻る/進むが動く |
| 図解・X投稿 | 7枚の図解と投稿リンクが対応し、外部埋め込みが遅くても本文を読める |
| 投票 | 7×4の全組合せで保存先・番号が現行と同じ。検査は送信先を置き換え、本番にテスト票を入れない |
| 引用・授業 | 引用文の論点とURLが一致。授業から移動でき、印刷プレビューで欠落・切れがない |
| JavaScriptなし | 要旨・全論点・資料・投稿リンクが読める。動的表示の失敗で本文が空白にならない |
| 次回更新 | ページ生成→山なみ更新→潮目→編集情報・授業節→数値同期を実際の経路で通しても、新表示と機能が残る |
| 入力が変わる場合 | 隔離した検証データで件数・順位を変えると表示も追従し、投票番号と関連資料は変わらない |
| 他テーマ | 共通部分を触った場合、既存ページとその再生成に不要な変更が出ない |

- 上記の消費税ページ生成・更新の回帰検査を追加する。非公開データを要する検査はローカルで行い、公開CIでは本文なしの検証データを使う。
- `verify_theme_page.py`、`verify_number_provenance.py`、`verify_top_page.py`、全体テスト、`run_public_checks.py` を実施する。
  新しい構造で既存検査が意図せず対象を素通りしないことも確認する。
- 変更差分・画面・生成し直した結果・残る制約をそろえ、公開実装と独立した品質確認を受ける。

完了条件: 読みやすい画面だけでなく、既存機能と通常の更新経路がそろって合格する。

  戻す際にも、その間に増えたSNSの集計データや投票を古い状態へ巻き戻さない。

- 課題77案1・2の10/19振り返りは維持し、今回の配置変更日を記録して同一の成果と混同しない。
