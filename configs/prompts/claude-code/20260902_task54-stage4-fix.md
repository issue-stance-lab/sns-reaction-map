### 4. 数え方を機械で再現できる形にする（本丸）

`data/verification/bukatsu-chiiki-sunk-continents.json` の各件に、次の2項目を足す。

```json
"sns_count": 0,
"sns_base": 1139,
"match_rule": {
  "type": "regex",
  "pattern": "資格要件|経験6年|6年以上",
  "scope": "text+summary",
  "machine_hits": ["2079117795217092828"],
  "excluded": [
    {"tweet_id": "2079117795217092828", "why": "指導者に学歴要件を求める意見で、東京都の6年以上という条件そのものへの言及ではない"}
  ]
},
"issue_bucket": {"issue_id": "bukatsu-chiiki-kakusa", "label": "地域格差", "count": 12}
```

決め方は次のとおり。**この定義を4件すべてに同じ意味で適用する。**

- **`sns_count` は「その争点そのものに触れた投稿の件数」**（論点のバケツ件数ではない）。
  `machine_hits` から `excluded` を引いた数と一致させる
- **`match_rule.pattern` は実際に打った検索式をそのまま書く。**「等」で終わらせない。
  論点で数えたい件は `"type": "issue_id"` にして `pattern` に論点IDを書く
- **`scope`** は正典のどのフィールドを見たか（`text` / `text+summary` / `text+summary+reason`）
- **`machine_hits`** は機械で一致した tweet_id の全部。**`excluded`** は、そのうち人が読んで
  「争点そのものではない」と外したものと、その理由。**外した理由を書かずに0件にしない**
- **`issue_bucket`** は参考値。近い論点のバケツ件数を出したいときだけ持たせる（無い件は項目ごと省く）

論点IDは `data/public/themes/bukatsu-chiiki.json` の `issues[].id` を使う。
`bukatsu-chiiki-kyoin`(教員の働き方323) / `-seido`(制度・移行プロセス256) / `-kyoiku`(教育的意義・機会215) /
`-ukezara`(受け皿・指導者164) / `-hiyo`(費用・家庭負担117) / `-kakusa`(地域格差12) / `-sonota`(その他52)。

### 6. 4件目「資格要件」を書き直す

争点名・生活への影響・件数を、**「東京都の実務経験6年以上という具体的な数値条件」まで絞る。**

- `topic`: 数値条件そのものを指す名前にする
- `life_impact`: 一次資料に書いてあることだけで書く。
  **「この条件の高さが担い手不足に関わっているか」のような因果の推測を入れない**
- **東京都という一自治体の例であることを本文に入れる**（3件目と同じ扱いに揃える）
- `sns_note`: 「資格の話は出てこない」ではなく「**資格を求める意見は N 件あるが、
  東京都の6年以上という条件そのものへの言及は0件**」の形にする

**判断が要る場合**: 絞った結果、3.3.2の「読者の生活への影響が具体的に特定できる」を
満たせないと判断したときは、**勝手に3件へ減らさずオーナーに聞く。**
