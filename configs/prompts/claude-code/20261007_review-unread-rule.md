# 依頼: 「未読割合」と、公開を止めるルール全般を、オーナーが分かる形で見直す

セッション開始時に、通常どおり `CLAUDE.md`・`OPERATIONS.md`・`TASK_BOARD.md` を読むこと。
**この依頼は「調べて、分かる言葉で説明し、選択肢を出して止まる」まで。ルールやコードは、オーナーが決めるまで変えない。**

## オーナーの言葉（これが出発点）

> この未読割合なるものも、よく分からないまま来ている。AIがどんどん分からないものを壁として作ってきた印象なので、
> ルール含めて検討したい。

つまり、論点は2つ。①「未読割合」という数字が何のためにあるのか、オーナーが納得できていない。
②同じ型の「公開を止めるルール」が、AIの判断で増え続けていて、全体像を誰も説明できていない。

## 先に知っておく事実（2026-10-07時点。すべてリポジトリの記録か、実測で確認したもの）

**未読割合とは**（`scripts/build_planet_data.py` の `independence_gate()` の条件3）
- 生成AIと著作権など「山なみ」形式のテーマでは、投稿を論点に分けたあと、**人（AI）が本文を1件ずつ読んで、理由別に仕分けた記録**
  （編集再読。例: `data/ai-copyright_issues-reread.json`）を持つ。これは、ページの「理由の内訳」の根拠になる。
- 新しく集めた投稿は、読んでいないので**毎回「未読」で増える**。論点ごとに「未読 ÷ 論点の意見の件数」が**4割を超えると、
  ページを作る検査（独自性検査）が止まり、更新を公開できない**。
- 同じ検査に、「再読済みの論点が意見全体の50%以上」「一次資料との突き合わせがある」「語られていない争点の母数が現在の意見数と一致」
  「テーマ固有の中心の問いがある」もある（全部で5条件）。警告用に30%の目安もある（`scripts/verify_reread_headroom.py`、管理画面に出る）。

**何のために作られたか**（記録上の説明）
- AdSense審査の診断で「自動生成コンテンツの疑い」が出ないよう、「中身が薄いテーマは公開ページを出さない」検査を生成器に持たせた
  （`independence_gate` の説明文）。「指示文に書いた禁止は別セッションで破られる。検査だけが残る」という設計思想。
- 「6割読め」のつもりが「6割で終わってよい」に骨抜きになった反省（課題62、`archive/tasks/task-62.md`）。
- 2026-09-13、オーナー判断で「読み飛ばし0件」の別枠を廃止し、4割の枠に統合した（`tasks/task-54.md` 2026-09-13の記録）。
  **ただし、4割という数字そのものの根拠が、記録から読み取れるか（誰が、どんな根拠で決めたか）は未確認。**
  そこから調べること。

**このルールで実際に困った記録**
- 2026-09-13 副首都: 「6割読めば足りる」と見積もったが、収集が止まっているテーマでは実質ほぼ全件が必要だった（`DATA_REFRESH.md`
  「編集再読の必要件数は『収集中か停止中か』で変わる」）。
- 2026-09-13 部活動: 2論点が39%・38%で、上限まで1〜2ポイント。次の収集で検査が止まる寸前だった（`tasks/task-63.md`）。
- 2026-09-15 部活動: 収集再開で2論点が上限に迫り、166件を本文から読む追い読みが必要になった（`themes/bukatsu-chiiki.md`、課題69）。

**今の数字**（生成AIと著作権。2026-10-07に、9/5の回の判定を置き換えた後）
| 論点 | 未読割合 | このまま収集を続けて上限（40%）に当たるまで |
|---|---|---|
| 学習データ・無断利用 | 27.8% | あと約3回 |
| クリエイター保護・権利 | 28.1% | あと約3回 |
| AI生成物の権利・創作性 | 32.9%（警告ライン超え） | あと約2回 |
| 技術競争・推進 | 27.3% | あと約3回 |
| その他 | 19.6% | あと約7回 |
前提: 1回あたりの増加は直近3回の平均、増えた分はすべて未読のまま、追い読みはしない。収集は約10日おき。
**つまり、何もしなければ、約1か月で更新が止まる。** これは9/13〜15の部活動と同じ型の詰まり方。

**もう1つの重要な実測**: 同じAIで同じ投稿を2回分類しても、論点は約34%食い違う（一致率66%、120件で測定）。
このぶれの大きさは、「割合」を厳密に守る意味を考えるときの材料になる。

## 依頼内容（この順で）

1. **平易な解説（A4で1枚まで）。** 「未読割合とは何か」「4割を超えると何が起きるか」「何を守るための数字か」を、
   専門用語を使わず、例え話つきで書く。誰のために守るのか（読者・AdSense審査・社内の誠実さ）も分けて書く。
2. **ルールの棚卸し。** 「公開や更新を止める検査・ルール」を全部洗い出して表にする。少なくとも次を含める:
   独自性検査の5条件、再読の警告（30%）、クレーム監査の照合遅れ（30日。課題99）、数字の出所検査、AI臭検査の基準線、
   ページ独自性検査、収集予定日の期限超過、公開前CI（`scripts/run_public_checks.py`）。
   各ルールについて、次の4点を記録から調べて埋める（分からなければ「記録なし」と書く。推測で埋めない）:
   ①誰が・いつ・なぜ作ったか ②実際に防いだ事故の実例 ③実際に止めた回数と手間、誤検知 ④オーナーが理解して承認した記録があるか。
3. **選択肢の提示。** 未読割合について、2〜3案を並べる。例（これに限らない）:
   - 現状維持（追い読みを計画的に行う）
   - 割合の代わりに、更新のたびに論点ごとに数件を抜き取って確認する方式
   - 基準の数字そのものを見直す（根拠を示して）
   - 別の仕組みで同じ目的を守る（例: 2つのAIの判定が食い違った分だけ読む）
   各案について、守れること・守れなくなること・作業量・リスクを書き、**「私ならこれ」と理由を1つ**添える。
4. **オーナーの判断を待つ。** 選択肢と推奨を出したら止まる。実装は、決まってから。

## 制約

- オーナーは非エンジニア。`CLAUDE.md` の「オーナーへの説明のしかた」に従う（結論先・専門用語は初出で一言・次の一手は1つ）。
- 公開中の数字・ページ・ルールは、オーナーの決定なしに変えない。変更を伴う作業は、専用の作業用コピー（worktree）で行う。
- 本件は2026-10-07の別セッションの作業（生成AIと著作権の「意見の推移」の導入、9/5の回の判定し直し。ブランチ `task/ai-trend`）と
  並行しうる。`scripts/build_planet_data.py`・`data/ai-copyright_issues-reread.json`・`scripts/build_trend_section.py` を
  触るときは、先に `git log` でそのブランチの状況を確認する。
- 確認していないことは、確認していないと書く。
