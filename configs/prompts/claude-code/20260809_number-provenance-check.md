## なぜこの作業をするか

**「表示される数字が合わない」が繰り返し起きている。** 2026-08-08〜09 の2日間で、
同じ形の問題が5回出た。

| 回 | 見つかった場所 | 対応 |
|---|---|---|
| 1 | 論点カードの見出しの手書き件数 | `sync_issue_counts.py` で生成 |
| 2 | `theme-seo.json` のべた書き件数 | `{total}` / `{opinions}` の差し込みへ |
| 3 | ビルダと `apply_theme_trust.py` が同じ文を書く | 書き手を1つに |
| 4 | 論点ナビ・論点セクション・アリーナのセクター | `issue_counts.sync` で生成（PR #59） |
| 5 | `sitemap.xml` の生成元にページが無い | 生成元へ追加 |

**共通する構造は1つ。**

> 数字の出所（正典）は1つなのに、**表示する場所が何か所あるかを誰も知らない。**
> 人が場所を列挙して、列挙した場所だけを同期している。
> 新しい場所が見つかるたびに、同期の仕組みと検査に足す。**列挙は終わらない。**

だからこの作業では、**列挙をやめる**。ページに出ている数字を総当たりで拾い、
**正典から導けない数字が1つでもあれば落とす**検査を作る。


成功の形: `欠落: []`（空のリスト）。

### 3. 検査スクリプトを新設する

新規ファイル: `scripts/verify_number_provenance.py`

**やること: ページ上のすべての数字に出所があることを確かめる。**

#### 3-1. ページから数字を拾う

対象は次の2つ。**特定のクラス名や要素に限定しない。ページ全体を見る。**

- `N件` / `N,NNN件`
- アリーナのセクター配列の `n: N`

#### 3-2. 正典から「導ける値の集合」を作る

`THEMES.yaml` の `sample_file` を読み、次をすべて集合に入れる。

| 種類 | 内容 |
|---|---|
| 総数 | 収集件数、関連件数、意見件数 |
| 1次元 | 論点別の件数、スタンス別の件数、強度別の件数 |
| **クロス集計** | **論点 × スタンス**、**論点 × 強度**（`heat-cell` / `side pos` / `side neg` がこれ） |
| 合算 | 論点カードが複数ラベルを合算しているテーマがあるので、2つの和まで許す |
| 割合 | 上記を意見件数で割った百分率（四捨五入） |
| **波ごと** | `fetched_at` で収集日ごとに切り出した件数（「世論の潮目」の比較対象がこれ） |

**全件ベースと意見ベースの両方**を作る。テーマによって `issue_counts.basis` が違うため。

#### 3-3. 本文の領域を除外する

代表投稿の本文と一次情報の引用には、正典と無関係な数字が入る（「令和7年の自転車関連事故は
67,470件」など）。**領域ごと除外する。**

除外する領域は設定に書く。`configs/{テーマ}-reaction-map.json` に
`number_provenance.exclude_selectors` のような形で、除外するクラス名・ID・
コメントで囲まれた範囲を列挙する。**スクリプトに直書きしない。**

#### 3-4. 残った数字を判定する

導ける集合にも無く、除外領域にも入っていない数字が残ったら、
`configs/{テーマ}-reaction-map.json` の `number_provenance.allow` に
**数値と理由をセットで**書かないとNGにする。

```json
"number_provenance": {
  "exclude_selectors": ["quote-block", "sources"],
  "allow": [
    { "value": 67470, "reason": "警察庁 令和7年中の自転車関連事故件数（一次情報）" }
  ]
}
```

**理由なしでは登録できない形にする。** 理由が書けない数字は、たいてい古い数字である。

#### 3-5. 出力

テーマごとに「拾った数字の数 / 説明できた数 / 説明できない数」を出し、
説明できないものは**行番号と前後の文脈**を添える。1件でもあれば exit 1。

```text
NG  bukatsu-chiiki: 説明できない数字 1件
      L142: …分析対象となった意見389件をAIが7つの論点に整理しました…
=== 数字の出所: 11テーマ / NG 1件 ===
```

### 5. 全テーマで通るまで、除外領域と許可リストを整える

最初は説明できない数字が大量に出る（2026-08-09 時点で173箇所）。順に片付ける。

1. **クロス集計**は 3-2 を直せば自動的に説明がつく。**まずここを厚くする**
2. **代表投稿・一次情報**は 3-3 の除外領域に入れる
3. 残ったものだけを1件ずつ見て、**古い数字なら直し、正当なら理由付きで許可リストへ**

**「面倒だから除外領域を広くする」をしないこと。** 除外を広げるほど検査は無力になる。
除外は「本文がそのまま載っている領域」に限る。

## 制約・注意

- **投票の選択肢の数を変えない。** 数が変わると `choiceIdx` の意味がずれ、
  Supabase Edge Function の再デプロイと既存票の破棄が必要になる。
  今回変わるのは**説明文の中の件数だけ**
- **公開している数字の意味を変えない。** これは表示の出所を揃える作業であって、
  数え方を変える作業ではない
- **`scripts/inject_tide_widget.py` を実行しない**（TASK_BOARD 課題38）
- **`social-samples/` 配下の未追跡ファイルを消さない**
- **`git checkout -- <ディレクトリ>` を使わない**
- 保護タグ（GA4 `G-K10S4YCZFH` / AdSense `ca-pub-2542211932832864` / Supabase / OGP）を壊さない
- main への直接コミット禁止

## 判断に迷ったら

**この検査は「数字を減らす」ためではなく「出所を持たせる」ためのもの。**
ページから数字を消して通す、除外領域を広げて通す、はどちらも目的に反する。

通らない数字が出たら、まず「これは正典から導ける値か？」を考える。
導けるなら 3-2 の集合が足りていない。導けないなら、それは古い数字か引用のどちらか。
