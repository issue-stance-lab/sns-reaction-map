## タスク: 副首都の「世論の潮目」ウィジェットを7論点へ揃える

### 出典
`configs/prompts/codex/20260807_fukushuto-taxonomy.md` の積み残し（2026-08-07）

### 目的
分類器を公開ページ側の7論点へ統一したが、ページ内の「世論の潮目」ウィジェットだけが
旧5論点のまま残っている。同じページの中で、アリーナ・カード・投票が7論点、
潮目のグラフだけが5論点という二重表示になっている。

### 背景（調査済み・再調査不要）
- `docs/fukushuto-reaction-map.html` に、7論点のラベル（定義・中身／候補地／都構想・維新／
  防災・災害／費用・財源／優先順位）と、5論点のラベル（副首都法案の是非／大阪・関西中心の問題／
  首都機能分散の必要性／財政・実現可能性）が**両方存在する**。後者は潮目ウィジェットの
  論点比較モードの `datasets.issue` だけが使っている
- 立場（stance）側は旧分類器と同じ3択のため連続しており、壊れているのは論点モードだけ
- 潮目の元データは 7/14 と 7/26 の Hermes 分類結果 約600件。これを7論点で分類し直すと、
  ウィジェットに表示している数字が変わる

### やること
1. 7/14 と 7/26 の各更新回のデータを、統一後の分類器（`scripts/fukushuto_taxonomy.py` 参照）で
   分類し直す。更新回ごとのファイルは改変せず、再分類結果は別名で保存する
2. 再分類の前に10件の試験分類を行い、論点の割り当てが妥当か確認する
3. 現在ウィジェットが表示している数字と、再分類後の数字の対照表を作って報告する
   （**数字が変わることの承認を得てから4へ進む**）
4. 潮目ウィジェットの論点モードを7論点で組み立て直す。`scripts/inject_tide_widget.py` の
   fukushuto 定義（`exclude_issues` など）も7論点に合わせる
5. 注釈テキスト（比較対象の日付・件数）を実際の更新回に合わせる
6. 立場モードは現状のまま。数字が変わらないことを確認する

### やらないこと
- 正典255件の再分類（アリーナ・カード・投票はすでに7論点で一貫している）
- アリーナの点データの再生成
- 他テーマの潮目ウィジェット

### 制約（必ず守る）
- 保護タグを壊さない: GA4 `G-K10S4YCZFH` / AdSense `ca-pub-2542211932832864` / Supabase / OGP
- ブランチ: `task/fukushuto-tide`。main 直接コミット禁止。**専用の git worktree で作業する**
- 論点・立場は `scripts/fukushuto_taxonomy.py` からのみ読む。ラベルを直書きしない
- 手順3の対照表を報告して承認を得るまで、公開ページを変更しない
- 投票の選択肢には触れない（`fukushuto-issue-stance-v1` / 21選択肢を維持）
