## タスク: 3種類の数字を分離し、投票ゲートを撤去する（S4）

### 出典

`WORK_PLAN_2026-08.md` §3 A-4
`WORK_PLAN_2026-08_SESSIONS.md` S4

### 前提（S1〜S3・S5 完了済み）

- トップの数値はすべて `THEMES.yaml` から生成される
- 根拠不明な表示（割れ度・ドーナツ・推移グラフ）は削除済み
- `verify_top_page.py` / `verify_theme_page.py` が存在し、負のテストで動作確認済み
- `elderly-license-revocation` に `arguments`（両側の強い論拠）と調査条件表示を実装済み

**このタスクは全11テーマが対象。** S5 で1テーマに入れた「調査条件の表示」を全テーマに広げ、あわせて数字の意味づけを統一する。

---

### 調査済みの事実（再調査不要）

#### ① 注意書きが2テーマに存在しない

```
constitutional-amendment    「世論調査ではありません」 0件
school-nickname-ban         「世論調査ではありません」 0件
```

他9テーマには1〜2件ある。**全テーマで統一されていない。**

#### ② 投票結果が「参加者投票」だと明示されていない

`docs/vote2d.js` の現在の文言：

```js
'投票が集計に追加されました。現在 <strong>' + voteTotal + '票</strong> が集まっています。'
```

これは「このサイトを訪れた人の任意回答」であることを示していない。SNS収集サンプルの件数と並ぶと、閲覧者には同じ種類の数字に見える。

#### ③ 投票前のぼかしゲートが残っている

```
docs/vote2d.js:98        inner.style.filter = 'blur(8px)';
docs/vote2d.js:107       'まず投票してから結果を見よう'
docs/topic-modern.js:212 function lockArenaUntilVote()
docs/topic-modern.js:258 lockArenaUntilVote();   ← 実行されている
```

**これは計画の記載漏れです。** 議論の段階で「投票前にマップをぼかして閲覧不能にする設計は撤去する」と合意していたにもかかわらず、`WORK_PLAN_2026-08.md` に項目として書き落とされていました。このタスクで回収します。

撤去する理由：

- 総投票数12件。ゲートは投票率を上げていない（効果が出ていない）
- 情報を見て考えたい読者を締め出し、先入観のない状態での投票を強制している
- 「賛否の奥にある理由を見渡せる形に」というサイトの方針と矛盾する

---

### やること

#### Step 1: 投票ゲートを撤去する

- `docs/topic-modern.js` の `lockArenaUntilVote()` の呼び出しを削除する（258行・298行）
- `docs/vote2d.js` の `blur(8px)` とオーバーレイ生成を削除する
- 関連する `arena-is-locked` クラスと CSS も除去する
- **投票導線自体は残す。** 結果の下、または論点の直後に自然に配置する

ページ内の推奨順序：

1. 30秒要約
2. 主要論点
3. SNS反応マップ（**最初から閲覧可能**）
4. 近い意見／反対側の意見
5. 自分の立場を投票
6. サイト参加者の投票結果

**サイト参加者の集計結果のみ、投票後に表示する仕様は残してよい。** ぼかすのはSNSマップではなく参加者集計のほうである。

#### Step 2: 3種類の数字を分離する

同じ色・同じグラフ・同じ見出しで混ぜない。

| 種別 | 表示ルール |
|---|---|
| **SNS収集サンプル** | 割合より件数を主表示。近くに調査条件（下記） |
| **サイト参加者投票** | 常に「**参加者投票 n=○○**」と明示 |
| **世論調査** | **実施していない**ことを明記 |

`vote2d.js` の文言を変更する：

```
現在 12票が集まっています
↓
このサイトの参加者投票 n=12（訪問者の任意回答です）
```

SNSマップと参加者投票で**同じ配色を使わない**。どちらかの系統色を変え、凡例で区別する。

#### Step 3: 調査条件を全11テーマに表示する

S5 で `elderly-license-revocation` に実装した表示を、`build_reaction_map.py` 経由で全テーマに広げる。

```
このマップの元データ: Yahooリアルタイム検索で取得した公開投稿 ○○件
取得期間: {sample_period}（記録がない場合は「記録なし」）
AI分類 + 人間による代表投稿の確認あり
社会全体の世論調査ではありません。
```

- 件数・取得元・期間は `THEMES.yaml` の `sample_file` / `sample_source` / `sample_period` から生成する
- `sample_period` が `unknown` のテーマ（6件）は**「記録なし」と正直に表示**する。推測で埋めない（TASK_BOARD 課題28）
- **注意書きは、そのページで最初に数字が出る箇所より前**に置く

#### Step 4: verify_theme_page.py に検査を追加し、全テーマで通す

```
=== 数字の分離 ===
OK  「世論調査ではありません」が存在する
OK  注意書きが最初の数値表示より前にある
OK  参加者投票に n=表記がある
OK  調査条件（取得元・期間・件数）が表示されている
OK  投票ゲート（blur / lockArenaUntilVote）が存在しない
```

- **全11テーマで exit 0 になること**
- 一括実行できるようにする（引数なしで全テーマを検査）
- **負のテストで NG / exit 1 を確認すること**

---

### やらないこと

- `arguments`（両側の強い論拠）の他テーマへの横展開（**別タスク**。今回は elderly-license のみのまま）
- `sample_period` の unknown 埋め（TASK_BOARD 課題28）
- トップページの変更
- 投票機能そのものの仕様変更（Supabase 連携・2Dキャンバス等はそのまま）
- 配色の全面刷新（分離に必要な最小限の変更のみ）

---

### 制約（必ず守る）

- 保護タグを壊さない: GA4 `G-K10S4YCZFH` / AdSense `ca-pub-2542211932832864` / **Supabase** / OGP
- ブランチ: `task/number-separation`。main 直接コミット禁止
- 数値をハードコードしない
- **投票データの送信・集計を壊さないこと。** ゲート撤去は表示の問題であり、投票の記録は従来どおり動くこと
- 既存の投票済みユーザー（localStorage に記録あり）が再訪したときに壊れないこと
- `verify_top_page.py` が引き続き exit 0
