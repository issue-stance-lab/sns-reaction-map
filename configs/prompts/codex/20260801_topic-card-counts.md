### 目的

トップページ上のすべての件数表示を単一の出所（`sample_file`）から生成し、
**「一部だけ生成されている」状態を今後は検査で必ず検出できるようにする。**

---

### やること

#### Step 1: テーマカードの件数を生成に切り替える

対象は `.topic-card` × 11枚の `.topic-meta`。

```html
<!-- 現在 -->
<div class="topic-meta">投稿 667件  |  論点比較（6論点）</div>

<!-- 変更後（id を付けて sync 対象にする） -->
<div class="topic-meta">分類済み <strong id="topic-count-consumption-tax-cut">667</strong>件  |  論点比較（6論点）</div>
```

- id 命名は問いカードの既存規則（`featured-count-{theme}`）に揃え、`topic-count-{theme}` とする
- `sync_portal_stats.py` に11テーマ分の置換を追加する
- **置換が0件マッチなら異常終了する**（既存の空振り検査の仕組みに乗せる）

#### Step 2: 用語を「分類済み」に統一する

現在ページ内で表記が割れている。

| 箇所 | 現在 | 変更後 |
|---|---|---|
| ヒーロー | 分類済み投稿 | そのまま |
| 問いカード | 分類済み ○件 | そのまま |
| テーマカード | **投稿 ○件** | **分類済み ○件** |

「投稿」だと収集総数と誤解される。数えているのは分類済みの有効件数なので統一する。

#### Step 3: 「今週の注目テーマ」カードを確認する

`.feature-card`（現在は副首都法案）にも手動更新の内容が入っている。

- 件数表示があれば同様に生成へ切り替える
- 表示テーマの選択は手動でよいが、**どのテーマを出しているかを `GROWTH.yaml` に記録する**（問いカードの `featured_questions` と同じ扱い）
- 記録がないと「説明できない選抜」になり、割れ度ランキングと同じ問題になる

#### Step 4: 次回更新日の静的初期値を生成する

```html
次回更新: 8月2日（<span id="update-bar-days">あと7日</span>）
```

`あと7日` は静的な初期値のまま。実行時にJSが上書きするため実害はないが、
JSが動かない環境やクローラには誤った日数が見える。

`refresh_at` から**初期値も生成**する。

#### Step 5: verify_top_page.py に「網羅」検査を追加する

**このタスクで最も重要な項目。** 個別の値の一致だけでなく、
**「ページ内のすべての件数表示が生成対象になっているか」**を検査する。

```
=== 件数の網羅検査 ===
OK  ページ内の「○件」表示は全て id 付き（手入力の件数が残っていない）
OK  テーマカード11枚の件数が sample_file と一致する
OK  問いカード4枚の件数が sample_file と一致する
OK  テーマカード合計 4,495 = ヒーロー表示 4,495
OK  件数の用語が「分類済み」で統一されている
```

- **「カード合計 = ヒーロー表示」の検査を必ず入れること。** これがあれば、今回のような「一部だけ生成」は総和のズレとして必ず検出できる
- id を持たない件数表示（`\d+件` にマッチするが id 属性がない箇所）を検出してNGにする
- **負のテストで NG / exit 1 を確認すること**（1枚だけ手入力に戻して検出されるか）

### やらないこと

- `arguments` の他テーマへの横展開（別タスク）
- `sample_period` の unknown 埋め（TASK_BOARD 課題28）
- テーマページ側の変更（`verify_theme_page.py` は回帰確認のみ）
- カードのデザイン変更（件数表記の変更に必要な範囲のみ）
- 注目テーマの入れ替え（記録を追加するだけ）

---

### 制約（必ず守る）

- 保護タグを壊さない: GA4 `G-K10S4YCZFH` / AdSense `ca-pub-2542211932832864` / Supabase / OGP
- ブランチ: `task/topic-card-counts`。main 直接コミット禁止
- **数値をHTMLに直接書かない。** 必ず `sync_portal_stats.py` 経由で入れる
- `docs/index.html` を `build_site_portal.py` で生成しない
- `verify_theme_page.py` が全11テーマで引き続き exit 0
