### やること

#### Step 1: config スキーマに `arguments` を追加する

**このスキーマは全テーマ共通になる。慎重に設計すること。**

`configs/elderly-license-revocation-reaction-map.json` に追加：

```json
"arguments": {

  "side_a": {
    "label": "義務化に賛成",
    "strongest": "…（最も強い論拠を1〜2段落）",
    "basis": "…（その根拠となる事実・統計）"
  },
  "side_b": {
    "label": "義務化に反対",
    "strongest": "…",
    "basis": "…"
  },
  "shared_premise": "高齢ドライバーの重大事故を減らしたいという目的は双方で一致している。",

  "unresolved": "年齢別の事故率を『免許保有者あたり』で見るか『走行距離あたり』で見るかで結論が変わるが、両方を揃えた公的統計が乏しい。",
  "sources": [
    {"label": "警察庁 交通事故統計", "url": "https://…"},
    {"label": "…", "url": "https://…"}
  ]

```

**選定基準（`about.html` または当ページに公開する）**

- 具体的な根拠がある
- 人物攻撃ではない
- 検証可能である
- 相手の立場を単純化していない
- 高リスク・未確認情報でない

#### Step 2: 執筆する

**これがこのタスクの本体。コード作業より時間をかけること。**

- `strongest` は「相手側が読んでも“確かにそれは一理ある”と思える」水準で書く。藁人形にしない
- `basis` には必ず検証可能な出典を伴わせる。数値を書くなら出典必須
- `unresolved`（まだ確認できていない点）を省略しない。**ここを書けることがこのサイトの独自性**
- SNS投稿の引用ではなく、**論拠そのものを編集して書く**。代表投稿は補足として下に置く

#### Step 3: `build_reaction_map.py` を対応させる

- `arguments` フィールドを読み、HTMLに描画する
- 配置は **「6つの論点」の直後、「SNS反応マップ」より前**
- 順序: 30秒要約 → 両側の強い論拠 → 共有している前提 → 本当の対立点 → 未確認の点 → 一次情報
- **「象限別の代表的な声」より上に置くこと**（代表投稿より論拠を優先する）
- `arguments` が無いテーマでは何も出力しない（他10テーマを壊さない）

#### Step 4: 調査条件を表示する

`THEMES.yaml` の `sample_file` / `sample_source` から、SNSデータの数字の近くに表示する。

```
このマップの元データ: Yahooリアルタイム検索で取得した公開投稿 211件
（取得期間: 記録なし／AI分類・人間による代表投稿の確認あり）
社会全体の世論調査ではありません。
```

`sample_period` が `unknown` のテーマは**「記録なし」と正直に表示**する。推測で埋めない（TASK_BOARD 課題28）。

#### Step 5: 検査を追加する

`verify_top_page.py` は**トップ専用**なので、テーマページ用に `scripts/verify_theme_page.py` を新設する。

```
=== elderly-license-revocation ===
OK  arguments 全フィールドが埋まっている
OK  sources のリンクが全て有効（HTTP 200）
OK  両側の論拠が代表投稿より前に出現する
OK  「世論調査ではありません」が存在する
OK  件数表示が sample_file の実数と一致する
```

**S1〜S3 と同様、負のテストで NG / exit 1 を確認すること。**
