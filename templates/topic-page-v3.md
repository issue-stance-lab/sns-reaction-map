# トピックページ標準フォーマット v3.1

この仕様は、SNS反応まっぷの各トピックページを「漫画 -> 投票 -> 2Dスタンスマップ」に接続するための正典です。Phase B以降のテーマ展開では、原則としてこの順序、セクションID、CSSクラス名、折りたたみ仕様を維持します。

## 1. ヒーロー

- セクション: `<section class="hero">`
- 共通UIを有効にするため、全テーマで以下を読み込む。

```html
<link rel="stylesheet" href="site-tokens.css?v=2">
<link rel="stylesheet" href="topic-modern.css?v=23">
<script src="topic-modern.js?v=8" defer></script>
```

- `<body>` は次の形式にする。

```html
<body class="summary-on-light"
      style="--topic-hero-image:url('images/{slug}-hero.webp')">
```

- 主要要素:
  - `.top-nav`: パンくず。`topic-modern.js` がテーマ名を補う
  - トピック種別バッジ
  - `<h1>`: テーマ名。画面上では末尾に「SNS反応まっぷ」を表示しない
  - `.question-line`: テーマの問いを1行で提示
  - `.lead`: 共通の分析方法
  - `.thirty-summary`: 最も声が集まった論点を伝える「議論の中心」1項目
- ヒーローは白背景、右側にテーマ画像をフェード表示する。テーマ固有CSSで旧グラデーション型へ戻さない。
- 高さは `topic-modern.css` の共通値を使う。
  - デスクトップ: `.hero` 555px、`.hero-inner` 553px
  - 720px以下: `.hero` 834px、`.hero-inner` 832px
- 短いテーマでも高さを縮めず、画像側の余白として見せる。長い文章を入れて共通高を超えない。

### 1.1 分析方法の共通文

題名下の `.lead` は、数字以外を全テーマで統一する。

```html
<p class="lead">収集したSNS投稿のうち、分析対象となった意見{分析対象件数}件をAIが{論点数}つの論点に整理しました。世論調査ではなく、SNS反応サンプルの論点比較です。</p>
```

- 変更してよいのは `{分析対象件数}` と `{論点数}` のみ。
- 収集件数、重複除去後件数、使用モデル、検索元、記事利用可件数などはここに並べず、「調査概要」または詳細データへ記載する。
- 分析対象件数は、直下の「分析対象の意見」カードと一致させる。

### 1.2 「議論の中心」

`.thirty-summary` の先頭に必ず次の見出しを置く。

```html
<header class="thirty-summary-title">
  <h2>議論の中心</h2>
</header>
```

- 項目は1つだけとし、最も投稿が集まった論点を扱う。
- 見出しに「最多論点」という分類用語を使わず、テーマ固有の問いへ翻訳する。
- `.conclusion-count` に件数、`strong` に読者が理解できる問い、`.conclusion-detail` に短い説明を書く。
- 独自スコアだけで断定せず、論点名、件数、割合など検証できる言葉を使う。
- 共通CSSの非対称フォーカスフレームと、初回だけの枠・件数アニメーションを使う。常時発光させず、`prefers-reduced-motion` では停止する。

### 1.3 ヒーロー直下の注目指標

旧来の「収集投稿・分類済み・意見投稿・最多論点」という処理件数4点セットは使わない。`.stats.insight-stats` と `.stat.insight-stat` を使い、そのテーマを理解するために有用な項目へ差し替える。

原則4枚で開始し、テーマ理解に不可欠な場合のみ追加する。全テーマで同じ4項目を機械的に使わず、次から必要度の高いものを選ぶ。

1. 分析対象の意見
2. 最も多い立場
3. 意見の割れ方（上位2立場を直接比較）
4. 最も話されている論点
5. 最も意見が割れた論点
6. 最も感情が強い論点
7. 条件付き・第三案
8. 意外な一致点
9. 判断を分ける核心
10. 当事者の声
11. 情報不足・判断保留

選定ルール:

- 「分析対象の意見」は必須。
- 割合を出すときは立場名と意味を併記する。
- 「激論度」のような算出根拠が見えにくい独自指標より、件数・割合・上位2立場の比較を優先する。
- 「最多」と「最も熱い」、「投稿数最多」と「最も割れた論点」を混同しない。
- 時系列推移はこのブロックに入れず、専用セクションで扱う。
- カードの色は `data-tone="debate|topic|option|insight|voice"` から意味に合うものを選ぶ。

### 1.4 論点解説セクション名

投票前の図解・論点整理セクションは、全テーマで次の形式に統一する。

```html
<div class="panel-title">
  <h2>このテーマを読み解く、{論点数}つの論点</h2>
  <span>{テーマ固有の短い補足}</span>
</div>
```

- 「投票前に読む」「○つの争点」は見出しに使わない。
- 見出しは「論点」で統一し、補足文のみテーマに合わせて変更できる。

## 3. 投票

- セクションID: `vote-section`
- 投票質問・選択肢文言はテーマconfigの確定文言を変更しない。
- 2問形式では、1問目を `#vote-step1`、2問目を `#vote-step2` とする。
- `topic-modern.js` が2問目の見出しを `.vote-step2-head` に統一し、補足文「選ぶと結果を表示します」と「← 論点を選び直す」ボタンを配置する。
- デスクトップは質問文と戻るボタンを横並び、720px以下は縦並びにする。
- 戻るボタンは投票を送信せず、1問目の選択画面へ戻して最初の論点ボタンへフォーカスする。
- 2問目の回答コンテナは `#vote-stance-btns`、各回答は `.vote-stance-btn` とする。デスクトップは選択肢数に応じた等幅グリッド、720px以下は1列にする。
- 回答ボタンは共通CSSで高さ・余白・角丸・上部の立場色・タイトル・説明・末尾の「選ぶ」を統一する。テーマ固有CSSで列数やボタン寸法を上書きしない。
- テーマHTMLに「答えたら開票します」「マップに表示します」などの個別補足が残っていても共通スクリプトが置換するが、新規テーマでは最初から共通文を使う。
- テーマ固有スクリプトで `.vote-step-back` を重複生成しない。
- 投票カード:
  - コンテナ: `#vote-buttons.vote-card-grid`
  - ボタン: `.vote-image-card`
  - ラベル: `.vote-card-label`
- 投票後は `#vote-result` を表示し、次を即時表示する。
  - `#vote-position-label`: あなたの選択
  - `#vote-position-text`: SNS分布との比較案内
  - `#vote-comparison.vote-comparison`: 「あなたの選択 vs SNS分布」の2カード比較
  - `#vote-bars`: 全選択肢の投票割合
- テーマ固有の結果HTMLは `topic-modern.js` が共通結果カードへ整形する。
  - 選択内容カード: 高さ92px
  - 操作列: 高さ40px
  - ボタン: 「𝕏 でシェア」「投票をやり直す」
  - `undefined` など未設定値を画面へ出さない
- Supabase投票ロジックは維持する。重複投票は `err.code === "23505"` と既存メッセージ判定の両方で扱う。

## 4. 論点アリーナ

- セクションIDは新形式の `issue-arena-section`、または既存互換の `stance-map-section`。
- 内側ラッパーは `#issue-arena-inner` または `#stance-map-inner` とし、最大幅 `720px`。
- 盤面ラッパーは `#sm-wrap` または `.arena-wrap` とし、最大幅 `640px`。
- Canvasの内部座標も `640 × 640` を正典とする。表示だけ640pxへ縮小する760px Canvasは使わない。
- 極座標の基準値は中心 `(320, 320)`、内周 `68px`、外周 `216px`、ラベル半径 `248px`、投票マーカー半径 `142px`。
- 内部順序は必ず「題名 → 説明 → 盤面 → あなたの場所の説明 → 凡例・フィルター」。既存HTMLの順序が異なる場合も `topic-modern.js` がこの順に整列する。
- デスクトップでは題名領域42px、説明領域84pxとし、全テーマで盤面をセクション上端から196pxの位置に揃える。
- 背景はAI著作権テーマを正典とする。
  - セクション: `#0f0e2e` + `images/shared/arena-bg.webp`（中央・cover）
  - 盤面: `#0f0e2e`
  - セクション余白: デスクトップ `42px min(6vw, 72px)`、720px以下 `30px 16px`
- 正典canvas ID（2枚構成の場合）:
  - ヒートマップ: `smCanvasHeat`
  - 点・軸・マーカー: `smCanvasMain`
- `ctx.filter` は描画アニメーション中に使わない。Safariで重くなるため、ヒートマップはフィルターなしまたは事前描画にする。
- 投票後はテーマのマーカー設定関数を呼び、`topic-modern.js` の `window.drawArenaUserMarker()` で「あなたはここ」を表示する。
- マーカーは白い外円、立場色の内円、パルスリング、白地の「あなたはここ」バッジを共通仕様とする。
- 選択した論点セクター全体は `window.drawArenaSectorHighlight()` で強調する。立場色の半透明面、4px外枠、同色の発光を使い、点マーカーだけで済ませない。
- 投票前は `topic-modern.js` がアリーナを8pxぼかして操作不能にし、「まず投票してからアリーナを見よう」を640px盤面の中央へ表示する。セクション全体の中央には置かない。
- 投票マーカー設定時に自動でロックを解除し、「選び直す」で投票を破棄した場合は再びロックする。テーマ固有スクリプトで別のロックUIを追加しない。
- 盤面下の説明は次の文へ統一し、投票前は非表示、投票後に表示する。

```html
<p id="your-marker-note-arena" class="arena-user-note" style="display:none;">
  投票した選択肢を「あなたはここ」マーカーで表示しています。
</p>
```

- 文字色は暗い盤面上で読める白系にし、中心円を白背景へ戻さない。
- ai-copyright の投票選択肢と象限対応:
  - 0: 「クリエイターを守るためAI規制を強化すべき」 -> 右上。規制賛成、クリエイター個人優先。座標目安 `(1.45, 1.45)`。
  - 1: 「技術革新を止めないよう規制は最小限に」 -> 左下。規制反対、AI産業・社会全体優先。座標目安 `(-1.45, -1.35)`。
  - 2: 「オプトアウトや対価支払いなど条件付きで共存」 -> 左上寄り。規制反対を基調に、クリエイター個人優先も残す。座標目安 `(-0.85, 0.95)`。
  - 3: 「よくわからない・まだ判断できない」 -> 右下寄り。制度整備への期待は残しつつ、産業・社会全体優先側の保留。座標目安 `(0.85, -0.95)`。

## 9. 編集・分析情報とArticle構造化データ

- 全公開テーマを `configs/theme-seo.json` に登録し、`scripts/seo/apply_theme_trust.py` で静的HTMLへ適用する。
- 画面上に公開日、最終更新日、編集・分析主体、SNS投稿の収集方法、AIを使った工程、サンプル分類であり世論調査ではない旨、訂正窓口を表示する。
- 既存の「データの集め方」欄は `.article-trust` に統合し、同じ説明を重複させない。
- JSON-LDは `Article` とし、画面と同じ `headline`、`description`、`datePublished`、`dateModified`、Organization名を使用する。
- `author` と `publisher` は `SNS反応まっぷ編集部`（Organization）とし、`about.html` へリンクする。
- 公開日・更新日はリポジトリ内で根拠を確認できる値だけを使い、再生成やSEOタグ変更だけを理由に更新しない。

## 実装上の保持条件

- GA4タグ `G-K10S4YCZFH` を残す。
- AdSenseコード `ca-pub-2542211932832864` を残す。
- Supabase URL/APIキーと投票ロジックを削除しない。未設定ページでは空文字の変数を維持し、ローカルフォールバックを動かす。
- OGPメタタグとcanonicalリンクは `SEO_META_START` / `SEO_META_END` ブロックで管理する。
- 漫画セクションと投票画像カードの既存資産は削除しない。
- 共通表示は `site-tokens.css`、`topic-modern.css`、`topic-modern.js` を正典とし、テーマ固有部分だけをインラインCSSに置く。
- 論点インフォグラフィックはパネル内幅いっぱい、比率 `1915 / 821`、`object-fit: contain`、`max-height: none` とし、文字や数値を見切れさせない。
- 共通CSS/JSを変更した場合は、全テーマのクエリ文字列（例: `topic-modern.css?v=13`）も更新し、ブラウザキャッシュを確実に切り替える。
