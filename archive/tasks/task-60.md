# 課題60: セッション開始時に読む文書を小さく保つ

**状態**: 完了（2026-09-04）。`TASK_BOARD.md` の索引化と `THEMES.yaml` の分割の両方が済んだ
**優先度**: 中（作業が止まるものではないが、放置すると全セッションの効率が下がり続ける）
**次にすること**: なし。運用ルールは末尾の節と検査（`verify_themes_yaml.py`）に移した
**詳細**: このファイル

## なぜ作ったか

`CLAUDE.md` は毎セッションの開始時に `company/COMPANY.md` `company/GOALS.yaml`
`README.md` `OPERATIONS.md` `THEMES.yaml` を読むよう指示している。
これらは作業の内容にかかわらず必ず読まれるので、**大きくなった分だけ、
実際の作業に使える余力が減る**。

2026-09-03 に他のAIから「開始時に読むべき文書が多く、特に TASK_BOARD が大きすぎる」と
指摘があり、実測したところ `TASK_BOARD.md` が単独で188KB・1,930行あった。
中身の9割は個別課題の経緯・実測ログ・レビュー指摘で、担当が決まった課題以外では読まれない。

原因は「課題の一覧」と「課題ごとの記録」を1ファイルに混ぜていたこと。
記録は課題が進むたびに増えるので、放っておくと必ず太る。

## 実施済み: TASK_BOARD の索引化（2026-09-03 完了）

| | 前 | 後 |
|---|---|---|
| `TASK_BOARD.md` | 1,930行 / 188,761バイト | 202行 / 14,216バイト |
| 課題の本文 | 同じファイルの中 | `tasks/task-{番号}.md` に27本 |
| 完了済み課題 | 索引に10件が残留 | `archive/tasks/` へ移動 |
| 「次にすること」の記入 | 8/37件 | 27/27件 |

- 索引に置くのは6欄（状態・優先度・期限・次にすること・判断待ち・詳細）だけ
- 状態欄の書き出しを `未着手` / `進行中` / `保留` に統一した。
  管理ダッシュボードはこの書き出しで区分を判定しているため、判定も正しくなった
  （例: 課題55は実際には進行中だが「未着手」に数えられていた）
- 再発防止に `scripts/verify_task_board.py` と `tests/test_task_board.py` を追加。
  索引の大きさ（上限3万バイト）・1欄の長さ（上限120文字）・詳細ファイルの有無・
  完了課題の残留を検査する
- 連絡メモの 2026-08-15 と 2026-08-30 の2件は課題55ですでに廃止された内容だったため、
  アーカイブへ移し、現行の公開元を書いた1行に置き換えた

## 実施済み: THEMES.yaml の分割（2026-09-04 完了）

着手前に、この課題が挙げていた3点を実測した。結果、**分割の境界は1本の線で引けた。**

| 調べたこと | 実測結果 |
|---|---|
| `THEMES.yaml` の内訳 | 44,166バイト／11テーマ。うち `notes` 欄だけで 35,039バイト＝**79.3%** |
| 機械が読むキー | 残り約9,100バイト。すべて1行の短い値 |
| `THEMES.yaml` を読むスクリプト・テスト | 54本。**うち `notes` を読むのは1本だけ**（`scripts/admin_dashboard/collect.py`） |
| その1本の使い道 | ダッシュボードのデータに詰めるだけで、`render.py` は一度も出力しない（実質未使用） |

「参照側の書き換えが大きすぎるなら閉じてよい」という当初の逃げ道は不要だった。
書き換えたのは1ファイルの1行だけで、残り53本は1文字も触っていない。

| | 前 | 後 |
|---|---|---|
| `THEMES.yaml` | 44,166バイト | 9,126バイト（-79%） |
| テーマごとの経緯 | 同じファイルの `notes` 欄 | `themes/{テーマ名}.md` に11本 |
| 開始時に読む文書の合計 | 90,957バイト | 55,917バイト（-38%） |

- 経緯は1文字も変えずに移した（移行スクリプトが「改行を取り除くと元と一致する」ことを検査）
- `THEMES.yaml` は YAML として読み書きし直さず、`notes` ブロックだけを文字列として削った。
  `refresh_topic.py` がキーの並びに依存した正規表現で書き換えるため、
  `yaml.safe_dump` を通すと壊れる
- 管理ダッシュボードの出力は、作成時刻と「未コミットの変更」の表示以外**完全に一致**した。
  `notes` が表示に使われていなかった裏付け

### 副次的に直ったこと

`refresh_topic.py` は `THEMES.yaml` を YAML ではなく**正規表現で書き換えている**。
折り返された長文の `notes` が同居しているのは、この方式では地雷だった。
追い出したことで、`^    {キー}:` の照合が構造的に安全になった。

### 再発防止

- `scripts/verify_themes_yaml.py` — 登録簿の上限2万バイト・`notes` 欄の復活禁止・
  1欄200文字・`themes/{テーマ名}.md` の有無と行数を検査
- `tests/test_themes_yaml.py` — 上の検査に加え、**`notes` を書き戻したら検査が落ちること**を確かめる
  （検査そのものが効かないと、この課題は静かに元へ戻る）
- 経緯を `notes` に書けと指示していた文書を全部直した:
  `.claude/skills/new-topic/SKILL.md`（2箇所＋チェックリスト＋登録手順）、
  `FACT_CHECK_GUIDE.md`（4箇所）、`DATA_REFRESH.md`（更新チェックリストに置き場を新設）、
  `OPERATIONS.md`（更新タイミング表）、`CLAUDE.md`（開始時の読み方）、
  `.claude/skills/new-topic/scripts/check_launch.py`（新テーマ公開前の検査に追加）
- 過去の記録（`tasks/` `quality/` `configs/prompts/`）は履歴なので書き換えていない

## 運用ルール（この課題が終わっても続けること）

- 開始時に読む文書へ「経緯」「実測ログ」「レビュー指摘」を書き足さない。
  それらは `tasks/` `themes/` `quality/designs/` `quality/reviews/` のいずれかへ置く
- テーマの経緯は `themes/{テーマ名}.md`。`THEMES.yaml` へ書き戻さない
- 課題を完了したら、その日のうちに `archive/` へ移す
- 検査: `python3 scripts/verify_task_board.py` と `python3 scripts/verify_themes_yaml.py`
