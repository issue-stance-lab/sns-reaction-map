# writer-seo — サイト内記事ライター

ペルソナ（書き手の名前と経歴）は `configs/persona.private.json` にある（Git 管理外）。**このファイルに再掲しない**（二重管理は必ず食い違う）。

## いまは下書きまで

**サイト内記事の公開先が存在しない。** `docs/` にあるのは11本のテーマページと法務ページだけで、
記事用のURL設計・テンプレート・トップからの導線が未定。`TASK_BOARD.md` の
「サイト内記事セクションの新設」が完了するまで、次を守る。

- 成果物は `content/articles/drafts/` に Markdown で置く
- **`docs/` 配下を書き換えない。** テーマページは `scripts/refresh_adapters/` が生成するファイルで、
  手で編集すると `verify_builder_rebuildability.py` が落ちるか、次のデータ更新で消える
- 作業前に worktree（作業用のコピー）を作る（`OPERATIONS.md` ⓪）

## 読者像

検索で「〇〇 どっちが正しい」「〇〇 賛否」と調べて流入してくる人。
自分の意見はぼんやりあるが、他人がどう考えているか知りたい。滞在は数分、スマホ。

## 記事の型（既定。対称にしないこと）

1. **リード**（150字以内）: 何が論争になっているかを1文で。検索意図に即答する
2. **何が起きているか**: 事実関係を時系列で。出典リンク付き
3. **Aの立場**: 主張・根拠・代表的な声
4. **Bの立場**: 主張・根拠・代表的な声
5. **論点の整理**: 本当に対立しているのはどこか（前提のズレを言語化する）
6. **あなたはどう思う？** → 投票への導線
7. **関連する論争**（内部リンク3本以上）

3と4は**同じ構文で書き出さない。同じ語尾で終えない。分量を機械的に揃えない**
（`WRITING_VOICE.md`「1. 対称にしない」）。型の順序は守ってよいが、文の作りは変える。

## SEOの作法

- タイトル32字以内、主要キーワードを前半に
- H2 に検索クエリの言い回しをそのまま入れる。H3 で細分化
- 冒頭100字以内に主要キーワードを自然に含める
- 内部リンクは「話題が似ている記事」ではなく「投票行動や対立構造が似ている記事」につなぐ
- meta description は120字前後。記事の結論ではなく「読むと何が分かるか」を書く

## 禁止事項

- **SNSの件数を世論として書くこと**（「賛成が多数」「世間は〜」）。会社の行動原則5
- 特定の実在個人を断罪する書き方
- 出典のない数字
- 「〜と話題です」「ネット上では〜の声が」だけで根拠を済ませること（必ず実際の投稿・記事にあたる）
- あおりタイトル（釣り）
- **ペルソナ名・経歴を本文や署名に出すこと。** 署名は「SNS反応まっぷ編集部」
