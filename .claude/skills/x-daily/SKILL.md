# X日次投稿

## 目的と基本方針

@sns_hannou_ma の投稿案を準備し、次の循環を作る。

> 特定の人に意味のある内容を、理解・反応しやすい形で出す → 会話する → 計測して次へ反映する

実際の投稿・返信の送信はユーザーが行う。候補、文案、添付画像、投稿後の確認事項を提示する。

到達しやすさだけで候補を選ばない。最初に「誰に、何を足せるか」を判定し、その後に返信数や
表示速度を見る。Xは固定の推薦ウェイトや配信保証を公開していないため、時間・画像・質問・URLに
関する経験則を絶対条件として扱わない。

日付を記録するときは実際の日付を使う。指示の日付と異なる場合は、書き込む前に確認する。

`/Volumes/M2-WorkSpace/Projects/副業/issue-stance-aggregator`

文面を作る前にレビューする。前週と同じ書き方を無意識に繰り返さず、今週変える変数を1つ決める。

## 日次手順

### 1. 今日の目的と対応可能数を決める

投稿ごとに目的を1つ選ぶ。

- 認知: 関心の近い人にアカウントを知ってもらう
- 会話: 論点について具体的な意見を集める
- プロフィール形成: 独自の論点整理をプロフィールへ蓄積する
- サイト流入: URL付き投稿からテーマページを読んでもらう

**URLなしリプライは1日2〜3本を目安とする（2026-10-31 オーナー指示）。**朝・昼・夕・夜のうち、
有力な候補が出た枠から順に出す。**4つの枠すべてを埋めることを目的にしない。**
2〜3本は上限ではなく目安で、内容適合（3節）を満たさない候補を数合わせで出さない。
**この回数をXのアルゴリズム上の閾値とは説明しない。**

**この本数は実測から決めている。本数を増やす方向は試して否定された。**
2026-10-15〜10-28に「1日8本」を試し、10-30に判定した。判定材料4つのすべてで試行前を下回った。

1〜2本=114／3〜4本=142／5〜6本=78／7本以上=23で、**4本を超えると単調に落ちる**
（試行期間内も同じ向き。7本以上の日=23／2〜6本の日=34）。だから目安は最も高い帯に置く。

判定の全文は `GROWTH.yaml` の `recurring.x-posting` と `content/x/weekly-reviews.md`（2026-10-30）。

論点ポスト（2026-10-08から凍結中）の2枠は空いたままだが、**本数を戻した効果が見えるまで同時に動かさない**。
復活させるかはオーナー判断待ち。

（2026-09-21に「1日0〜3件」から「朝・昼・夕・夜の1日4回を目安」へ変更。2026-10-15に8本の試行を開始し、
2026-10-31にその判定を受けて1日2〜3本へ戻した。）

どうしても出ない場合は、試した検索語をすべて列挙し、何が理由で落ちたかを示す。

**「どちらかを選んでください」では足りない。「残り1本」と数字で書く**（2026-10-31、夜に2案を出して2案とも投稿され、その日の合計が目安の2〜3本を超えて4本になった）。

### 2. Xで素材を探す

検索を始める時点から、将来X APIへ移行した場合の費用計算に使う件数を数える。ブラウザやアプリが
返した数ではなく、実際に検索結果として読んだ範囲を対象にする。

- 検索を実行した回数
- 読み込んだ検索結果の投稿数
- 24時間内の重複を除いた確認投稿数
- 個別ページを開いた投稿数
- 重複を除いた投稿者数
- 自アカウントの投稿数
- 内容適合の検討対象に残した候補数

途中から数え始めた、画面上で件数を確定できなかったなど完全でない場合は、推測で補わず未取得項目を
空欄にし、`--incomplete`で記録する。投稿本文、URL、アカウント名は実測台帳へ保存しない。

X本体の「最新」タブを使う。検索語は公開中テーマと当日のニュースに合わせ、古い固定クエリを
そのまま使わない。基本形:

```text
(テーマ語 OR 関連制度名 OR 当日の固有語) -filter:replies -filter:retweets min_faves:10
```

規模のある会話も確認するときは `min_faves:80` でも検索する。どちらも候補生成用であり、
いいね数を採用条件にしない。速報日にはいいね下限を外すか下げる。

**検索語を作る前に、その時点のニュースを確認する（2026-10-08の反省）。**
10-08の朝、テーマ名と質問語だけで5回検索して「候補なし」と報告したが、実際には前夜に
「立憲民主党が食料品消費税ゼロを取り下げ給付へ方針転換」（朝日・10-07常任幹事会）が出ており、
`給付` `給付付き税額控除` `立憲` を検索語に入れた回で初めて候補が出た。**原因は3つ。**

1. 検索語がテーマ名（`消費税減税` など）だけで、**その日動いた固有語を入れていなかった**。
2. **「最新」タブの1画面目しか読まなかった。**最新タブは時刻順なので、夜中に出た投稿は朝には流れている。
   **最低2画面はスクロールし、必要なら「話題のポスト」タブも見る。**
3. **質問・不確かさの形に絞る条件を、候補ゼロの時点でも外さなかった。**週の変数の条件は
   候補が取れるときの絞り込みであり、**ゼロなら条件を外して内容適合で選び直す**（外したことを記録に書く）。

当日のニュースは、Xの「本日のニュース」欄か、テーマ語だけ・質問語なしの検索（`f=live` と
「話題のポスト」の両方）で確認する。

検索結果から次を取得する。

- 投稿URL、本文、投稿者、投稿時刻
- 返信数、表示数、経過時間、表示速度（取得できる場合）
- 元投稿が扱う論点と、想定される読者

ブラウザごとの取得方法と過去の選定検証は `references/selection-evidence.md` を必要時に読む。

### 3. 内容適合を先に判定する

候補ごとに以下を確認し、1つでも満たせない場合は見送る。

1. **読者適合**: 投稿者だけでなく、その返信欄を実際に読む人を具体的に一言で表せ、想定読者と一致するか
2. **追加価値**: 元投稿にない事実、区別、判断基準、具体例、未解決点のどれかを足せるか
3. **関連性**: SNS反応まっぷの公開テーマと自然につながるか
4. **会話適合**: 元投稿の目的と文脈に対し、返信が自然な補足、問い、具体化になっているか
5. **自立性**: 自サービスの宣伝をしなくても、返信単体で読む価値があるか
6. **安全性**: 人格攻撃、断定、分断の煽り、遺族への配慮不足がないか
   **元投稿だけでなく、そのアカウントの直前の投稿も見る。**返信は相手のページで、相手の他の投稿の隣に並ぶ。
   人の属性や身体について書いた投稿の隣にこちらの返信が表示される状態は、到達の大きさでは償えない。
   2026-10-18夜、1,950表示で足せる事実もある自転車の候補を、この理由で見送った。

元投稿の言い換え、一般論だけの感想、無理な問いかけしか作れない候補は採用しない。
テーマが関連するだけでも採用しない。求人、広告、告知、事務連絡など議論を主目的としない投稿は、
その目的を妨げず、投稿者と返信欄の読者にとって返信する必然性がある場合だけ採用する。
元投稿を自分の論点へ変えるだけの返信は見送る。

**アカウントの立場だけで見送らない（2026-10-13 オーナー判断、2026-10-14 明文化）。**
支持政党や思想を明示したアカウント、アンケート形式のアカウントは、**それだけでは見送り理由にしない。**
判定材料は2つだけ。**①その返信欄に実際の議論があるか（返信数・投票数などで確かめる）。
②こちらが一次資料で足せる内容があるか。**この2つを満たせば、立場が賛成側でも反対側でも候補に出す。
AIの判断で候補から落とすと、オーナーの目に触れないまま機会が消える。**迷ったら、文案と判断材料
（返信欄の実態・フォロー価値・その日の本数）を添えて提示し、採否はオーナーが決める。**

**それでも除外し続けるのは次だけ。** 政治家・候補者・政党の公式アカウント、政党の役職者
（「特別顧問」などプロフィールに役職の記載があるもの）、政府広報アカウント、bot、遺族案件。
**プロフィールに役職が書かれていないか、候補にする前に必ず開いて確かめる**
（2026-10-14、「前衆議院議員・日本保守党特別顧問」と判明して直前に見送った例がある）。

**返信が返せなかった相手は、候補に出さない（2026-10-31 オーナー指示）。**
こちらの返信に相手が返信を返してきて、**こちらが一次資料では答えられずに止まった相手**は、
以後の候補から外す。**該当: @774nyannyan（猫ジャンキー）。**2026-10-16の返信に
「そこまで税金使ってやる必要があるのか」と返され、是非を問う問いに判断材料しか出せず、
いいねだけで終えた（2026-10-17）。**同じ相手に二度目を出すと、同じ所で止まる。**
立場での除外ではなく、**会話の実績による除外**。新しい相手が見つからないときの穴埋めにも使わない。

**書く内容は、相手の立場に関係なく同じにする。**条文・文書に何が書かれているかだけを書き、
賛否・人物評価・見通しを書かない。これが守れていれば、どちらの側のスレッドでも加担にならない。

候補ごとに、返信の採否とは別に「フォロー価値」も判定する。対象アカウントがそのテーマの当事者・
専門家・実務者か（例: 部活動の地域移行なら地域クラブ運営者・教員・教育行政、高齢者免許返納なら
安全運転支援や地域交通の実務者）を見る。テーマと無関係な一般アカウントや、フォロー返し狙いに見える
アカウント（プロフィールに数を戻す旨の記載がある、無関係な宣伝目的など）は対象にしない。
返信を見送った候補でも、フォロー価値があれば別途示す。

### 4. 届きやすさで並べ替える

内容適合を通過した候補だけを、次の参考情報で並べ替える。

1. **相互フォロー関係にある**（2026-09-21追加。プロフィールの「フォローされています」表示等で確認する。
   公式アルゴリズムの重み表で、相互フォロー相手への通常ポストへの返信は予測重みが5.0→20.0になる。
   ただしこれだけで採用理由にはしない。内容適合（3節）を満たした候補の中で優先順位を上げる材料に留める）
2. 元投稿の返信欄が過密でない
3. 現在も表示が伸びている
4. 話題の時事性が高い
5. 直近に接触していない投稿者・読者層である

返信100件超は原則見送る。返信10件前後、表示速度、経過時間は参考値に留める。
「高速度＋少返信」は内部実績で見つかった仮説であり、内容適合を覆す採用条件や見送り条件にしない。

### 5. 投稿文を作る

`references/writing.md` の手順で設計・作成・推敲する。1投稿1テーマにし、最初の一文だけで
論点または追加価値が分かるように書く。冒頭は異なる3方向を内部で比較し、本文が実際に返す価値と
最も合う1案を採用する。元投稿への敬意を保ち、次のいずれかから内容に合う型を選ぶ。

- 論点整理: 混ざっている2つの問いを分ける
- 視点追加: 見落とされている当事者、費用、運用、検証方法を足す
- 具体化: 判断に必要な指標、期限、責任主体を示す
- データ提示: 出典の確認できる事実から観察を示す
- 未解決点: 現時点で分からないことを明示する
- 問いかけ: 読者が具体的に答えられる問いを1つ置く

**【2026-10-17 オーナー指示】説明だけで終えない。個人アカウントへの返信には、感想や意見を一言入れる。**

- **報道アカウント宛（@asahi など記事の紹介投稿）は、説明だけでよい。**
- **個人アカウント宛は、相手の言い分を受け止める一言か、資料を読んだ感想を入れる。**
  例:「たしかに、そこは別の問いですね」「条文を読むと、お金の話は意外なほど薄いです」
  「比べる相手がなくて少しもどかしいです」。
- **これは賛否の表明ではない。**政党・政治家・政策への賛成反対、人物評価は引き続き書かない。
  入れてよいのは、**①相手の論点と自分が足す事実がずれていないかの確認 ②資料を読んだ印象
  ③事実から自然に出てくる観察**の3つまで。
- **きっかけ**: 2026-10-14 @higakubo、10-15 @takuyasan_0307、10-16 @774nyannyan と、
  **3回続けて「相手は是非を論じているのに、こちらは文書の記載を返した」という返信が付いた。**
  オーナーから「最近の文章が説明により過ぎの印象」との指摘。

質問は自然に会話を生む場合だけ使う。すべてを「？」で終えない。直近3本の冒頭、語尾、本文構造、
「AとBは別」「分けて考える」などの対比表現を確認し、同じ定型を繰り返さない。

画像は必須ではない。次の場合だけ、内容に最も合う `*-infographic-wide-*.webp` を付ける。

- 文章だけより論点を速く理解できる
- 元投稿への返信として唐突にならない
- 画像内の内容と投稿文が直接対応する

画像が主張を増やしすぎる、文章だけの方が自然、事故・遺族案件で不適切になり得る場合は画像なしにする。
画像を提案するときは、会話内表示と絶対パスのローカルリンクを付け、採用理由と、Xへ入力できる
代替テキストを独立した欄で書く。代替テキストには、画像内の重要な文字と何を示す図かを具体的に入れる。
画像ファイルは `rg --files docs/images | rg '<テーマまたは論点>'` などで実在を確認する。確認できないパスを推測で作らず、
その場合は「画像候補の実在を未確認」と書く。画像なしに変更しても、画像内の複数の論点を本文へ詰め戻さない。

禁止事項:

- URLなしリプライへサイトURLや宣伝文句を入れる
- 強い賛否や人物評価を表明する
- 「SNSでは○%が賛成」「意見が真っ二つ」「意外な結果に」「あなたはどっち？」を使う
- 確認できていない数字・因果関係・アルゴリズム攻略法を断定する

### 6. 論点ポストと流入投稿を作る

論点ポストは、その週の枠が残り、プロフィールへ残す価値がある題材だけ作る。問いかけ型を優先せず、
独自の整理が最も伝わる型を使う。画像も目的に応じて選ぶ。

流入投稿は `X_POSTING_GUIDE.md` に従う。投稿単体で価値を渡したうえで、続きを読む理由を明示する。
URLにはUTMを付け、URL付き枠を消費する。

### 6.5 提示する前に、文を自分で確かめる【2026-10-19 オーナー指示】

**§5 の「説明だけで終えない」は 2026-10-17 に書いたが、10-18・10-19 で元に戻った。**
**ルールを足しても守れなかったので、出す前の確認工程として置く。**よみやす検査と同じ位置で必ず回す。

各案について次の4つを自分で確かめ、**答えを投稿案の提示文に書く**（オーナーからも見えるようにする）。

| # | 確認 | 直し方 |
|---|---|---|
| 1 | **1文目は、相手の状況・発言内容を受けているか。相手への評価も、正しさの判定も不可** | 1文目に資料名・条番号が入っていたら書き直す。**単語を拾っただけも不可。**「よく読んでいますね」「助かります」のように相手の能力・努力を採点するのはもっと不可。**「〜のとおりでした」「〜とも重なります」のように、相手が書いた事実を追認する冒頭も不可【2026-10-24 オーナー指示】**（`references/writing.md` 第5節） |
| 1.5 | **その一次情報は、相手が同じ資料を開いても気づかないか【2026-10-24 オーナー指示】** | 見出しに書いてある数字、計算すれば出る数字は補足ではない。**資料を読んで初めて分かることが1つもないなら、その候補は出さない**（`references/writing.md` 第5節） |
| 2 | **一言を消しても文が成立するか** | 成立するなら、それは説明文。一言が後付けになっている。**先に「自分は何を思ったか」を決め、事実はそれを支えるために引く** |
| 3 | **数字はいくつ入っているか** | **1投稿に2つまで。**3つ以上並べたら説明に寄っている。削る |
| 4 | **直近3本と冒頭の型が同じでないか** | 同じなら変える（§5 にも同趣旨の記載あり） |

**条番号は、相手が条文を話題にしているときだけ書く。**相手が条文に触れていなければ落とす。

**提示のときは、冒頭を3案つくって型とともに並べ、採用案と選んだ理由を1行で書く【2026-10-20 オーナー指示】。**
`references/writing.md` 第2節は「内部で比較して採用案だけを示す」としていたが、
**内部で比べたかどうかはオーナーから見えないため、2026-10-18〜20 に工程ごと飛ばしていた。**
その結果、毎回いちばん出しやすい型（資料から入る「データ提示」＋「結論」）だけが選ばれ、
**1文目が4本続けて資料から始まる状態になった。**3案を提示文に出せば飛ばせない。

**なぜ必要か**: よみやす検査は**「読みやすい説明文」としての100点**を出す。
数字が6つ並んでいても、条番号から始まっていても止まらない。
**中身を見る確認が、提示の直前に無かった。**

**ドリフトの起き方（記録）**: 2026-10-17〜18 に一次資料を大量に登録した結果、
**候補選びの基準が「どの投稿なら資料を貼れるか」に変わっていた。**
本来は「どの投稿なら自分が何か言えるか」。
10-19昼、オーナーから「前よりも、より客観的な、統計的な話しか出なくなりました」との指摘。

**書き直しの例（2026-10-19 @FptakkenshiDan 宛）**

| | 文 |
|---|---|
| 直す前 | 「1％相当という枠は、法案にも入っていました。**第10条第3項**が、令和9年度の総額を「消費税の収入見込額を超えないようにすることを考慮して」政令で定める、としています。逆算の見方は条文とも合いますね。上限は報道で出ていますが、下限は中間とりまとめで3案が併記されたままです。」 |
| **直した後（投稿）** | 「**逆算、当たっていると思います。**法案は総額を先に消費税の収入見込額の範囲で考えると書いていて、枠が先にあって頭割りという作りです。**気になるのは上限より下限のほうで**、ここはまだ3案が並んだまま。どこで線を引くかで、対象から外れる人がかなり動きます。」 |

**変えた点**: ①1文目を相手の作業への答えにした ②条番号を落とした（相手は条文の話をしていない）
③数字を1つに減らした ④**「気になるのは上限より下限のほう」が意見**。上限より下限のほうが、
対象から外れるかどうかに効く。

### 7. 投稿案を提示する

候補の有無にかかわらず、提示前に次を実行して検索実測を保存する。`<値>`は今回の実数へ置き換え、
取得できなかった引数は省略する。Codexアプリは`--source codex_app`、Claudeアプリは
`--source claude_app`を使う。

```bash
python3 /Volumes/M2-WorkSpace/Projects/副業/issue-stance-aggregator/scripts/record_x_search_usage.py \
  --source <codex_app|claude_app> --mode chrome \
  --queries <検索回数> --results-loaded <読み込んだ投稿数> \
  --unique-posts <重複除外後の投稿数> --post-details <個別確認数> \
  --unique-users <投稿者数> --owned-posts <自投稿数> --candidates <候補数>
```

保存に失敗した場合は投稿案を失敗扱いにせず、回答に「検索実測を保存できなかった」と理由を明記する。
保存結果に`counts_complete: false`がある場合も、その旨を投稿案の末尾へ表示する。

## 投稿後の運用

ユーザーが投稿したら、当日中に実質的な返信が付いていないか確認する。返す場合は、人物評価に乗らず、
追加質問・根拠・判断基準で会話を前へ進める。「ありがとうございます」だけの返信を量産しない。

**投稿文に誤りが見つかったときは、こちらから訂正ポストを出さない（2026-10-12 オーナー指示）。**
指摘の返信が付いたときに、その返信で訂正する。誤りの内容と、なぜ気づけなかったかは
`content/x/posts.md` に必ず記録する（公開するかどうかと、記録するかどうかは別）。

**閣議決定・国会提出があった日は、法案本体（概要・要綱・法律案）を取りに行ってから書く。**
報道と大綱だけを根拠にしない。2026-10-09の閣議決定後、大綱だけで3日間6本投稿し、
「軽減税率の対象」と「今回の引下げの対象」を同じものとして書いた誤りが出た
（前者は飲食料品＋定期購読新聞、後者は飲食料品だけ）。

投稿実績の記録、24〜48時間後の表示計測、`THEMES.yaml` とトップページの同期は
`references/measurement.md` に従う。投稿直後の表示数で成否を判断しない。

## 週次レビュー

週1回、`content/x/weekly-reviews.md` に次を記録する。

- 到達: 表示数と自アカウント通常値との差
- 会話: 返信、引用、リポスト、返信内容
- 関心: いいね、プロフィール訪問、フォロー（取得できる範囲）
- フォロー実施: 今週こちらからフォローした人数・相手・当事者性の根拠（0人の週があってもよい。頭数目標は置かない）
- 流入: URL投稿のクリック、GA4のX流入、サイト内行動
- 検索: Google検索での表示回数（Search Console、以下GSC）。先週と比べてどうか、取得自体が動いているか。
  X運用そのものの数字ではないが、`fetch_growth_kpi.py`が同じ呼び出しで取得するのでここに含める
- 再現条件: 対象者、追加価値、冒頭、形式、画像、時間帯、投稿後対応
- 文章要素: 冒頭の型、具体化の方法、本文構造、締め方、定型表現の重複

平均だけでなく中央値と外れ値を見る。データが少ない間は勝ち型を断定せず、次週に変える変数を1つだけ
決める。頻度、画像、冒頭、投稿形式を同じ週に同時変更しない。
