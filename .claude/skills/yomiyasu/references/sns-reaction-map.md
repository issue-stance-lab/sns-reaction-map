# SNS反応まっぷ固有ルール

## 変更してはいけないもの

- SNS投稿サンプルを世論と書き換えない。
- 数字、単位、日付、固有名詞、出典名、URL、UTMパラメータを変えない。
- 事実、SNS上の意見、編集部の評価、推測を混ぜない。
- 推量を断定へ強めず、断定を推量へ弱めない。
- 賛否どちらかを愚かに描かない。双方が守ろうとしているものを残す。
- 「無作為抽出の世論調査ではなく、SNS公開投稿のサンプル分析」のような、母集団の限界を示す否定は残す。
- 公開文に内部ペルソナの名前や経歴を出さない。

## よみやすを優先する項目

- 平均文長は30〜45字を目安にする。長いことだけを理由に分割しない。
- 読点は1文0〜2個を目安にする。
- 絵文字、em dash、文末コロンを公開本文に使わない。
- CTAは絵文字ではなく、リンク先で分かることを平文で示す。
- 同じ文末が3回以上続く場合は、意味と文の働きを変えずに整える。
- 不自然な非生物主語、比喩動詞、空疎な前置き、意味を担わない否定対比を直す。

## 媒体別

### note

`*-FINAL.md` と `*-CANDIDATE.md` は、最初の区切り線 `---` より後を公開本文として検査する。区切り線より前の作業メモ、画像プロンプト、チェックリストは対象外。記事の主張、反論、根拠、結論の比重を変えない。

### Website・SEO記事

WebsiteのHTMLは、共通UI、免責、フッター、スクリプトを除いた編集本文を検査する。生成物を直接直さず、発注書・設定・adapterなど再生成元を直す。

### X

280字制限と1投稿1主張を優先する。平均文長は投稿全体の合否条件にしないが、主語不明、過剰な読点、絵文字、比喩、定型の対比は直す。投稿操作は行わず、候補だけを作る。

## 判定

`warn` と `error` は完成を止める。`info` は内容を確認するが、必要な否定対比なら残してよい。リンタースコアを上げるために意味を削ったり、新しい説明を足したりしない。

## 機械で止まる項目と目視で確認する項目

`scripts/review_with_yomiyasu.py --strict` が見る項目と、人が見る項目の分担。しきい値と、文の長さを数えない行は `configs/yomiyasu.json` の `mechanical_checks` で変える。

**機械で止まる（warn。終了コード1）**

- 上流リンター: 絵文字、行末のコロン、同じ文末の3連続、スロップ語彙、決まった形の比喩動詞と前置きの定型句、太字と箇条書きの出すぎ、英単語前後の半角空白、見出しの補足カッコ
- このスクリプト: ダッシュ記号（U+2014、U+2015、U+2500、U+2013。長音記号「ー」U+30FC は対象外）、1文の読点が4個以上、1文が80字を超える

**機械は知らせるだけ（info。止めない）**

- 「AではなくB」（上流リンター）
- 1文の読点が3個、平均文長が25字未満または55字超（このスクリプト。Xは平均を見ない）

**目視で確認する**

- 平均文長が30〜45字の目安に近いか。出力の「文の長さ」の行を見る。機械は25〜55字の外だけ知らせる
- 読点が0〜2個の目安に収まっているか。機械は3個から知らせ、4個から止める
- CTAが絵文字ではなく、リンク先で分かることを平文で示しているか
- 不自然な非生物主語、比喩動詞、空疎な前置き、意味を担わない否定対比。機械が拾うのは決まった形だけ
- 数字、URL、出典、引用、断定の強さが動いていないか。`--original` を渡すと、数字とURLの増減は機械でも比べる
- SNS投稿サンプルを世論と書いていないか。賛否の書き分けに偏りがないか

**読み方**

- 文の長さと読点の数を数えない行: 見出し、箇条書き（`-` `*` `1.` と、中黒「・」で始まる行）、URLで始まる行、`▼` で始まる画像の指示行、「データについて」「制度についての記述」で始まる注記、表、引用、HTML、インデント行、コードブロック。ダッシュ記号の検査だけは、これらの行にも掛かる（フロントマター、コードブロック、インラインコードは除く）。
- 80字を超える文も、長いことだけを理由に分けない。手段・理由・順序・対比のつながりを後ろの文に残せるなら分ける。分けると意味が変わる文は残し、理由を納品時に報告する。
- 指摘の行番号（L）は、検査する本文の中の行番号で、ファイルの行番号ではない（noteは最初の区切り線より後ろ、websiteは抽出した見出しと本文）。読点、長文、ダッシュの指摘には該当箇所の抜粋が付くので、それで探す。
