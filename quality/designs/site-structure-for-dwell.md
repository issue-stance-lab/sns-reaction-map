# サイト構成案：部活動ページを「1枚の作品」から「回れるサイト」にする

作成: 2026-09-05 ／ 対象: 課題54（段階8-B完了時点の部活動ページ）
関連: 課題51（記事セクション）・課題55（ドメイン移行）・課題15（AdSense）
状態: **順番はオーナー決定済み（2026-09-05）。段階10（残り9テーマの作り替え）を先に終わらせ、
そのあとで横断ページを作る。**中身の設計は提案のまま
オーナー向けの図つき版: https://claude.ai/code/artifact/7d0ebdb8-5380-423d-81b1-46e8378d6941

## 結論

1. **1ページの滞在は、段階8-Bでほぼ解けている**（中央値4〜6分の見込み）。
   残っている穴は中身ではなく、**読み終わったあとの行き先が無いこと**。
2. サイトの滞在は「1ページの滞在 × 1訪問で見るページ数」。いまの構成は
   **縦（1テーマを深く）だけがあって、横（テーマをまたぐ）が1本も無い**。
3. 横を作る材料は**すでに全部データにある**。7テーマ48主張の一次資料照合
   （そのとおり21・少しずれる18・裏が取れない9）。**追加の取材はいらない。**

## いまの構成と、どこが行き止まりか

```
トップ（10テーマのカード一覧）
 ├ 部活動ページ（新・山なみ）   ← ここだけ深い。ただし未公開・未マージ
 ├ 消費税減税ページ（旧2D）
 ├ … 残り9本すべて旧2D
 └ about / privacy / disclaimer / image-policy / usage
記事: 0本（課題51は公開先が無く待機中）
横断ページ: 0本
```

読者の動きはこうなる。**山なみページを6分読む → 末尾の探査記録で終わる →
次に押せるものが「旧2Dの別テーマ」しかない。**段差が大きく、そこで帰る。

参考の実数（GA4 2026-08-22）: 週11人・PV170・1訪問4.146ページ。
ただし母数が小さく、8/10時点の内訳では**テーマページは最多でも6PV**で、
見られているのはトップとaboutだった。滞在の設計は効くが、**流入が無い間は数字に出ない。**

## 提案する構成

**3層＋1本の横串。**

| | 役割 | 本数 | 滞在への効き方 |
|---|---|---|---|
| 層1 入口 | トップ・記事・X・検索 | トップ1＋記事N | 入ってもらう。滞在は稼がない |
| 層2 本編（縦） | テーマページ＝山なみ1本道 | 10 | **主エンジン**。1本4〜6分 |
| 層3 横断（横） | テーマをまたいで初めて意味が出る場所 | **2本だけ** | **第2エンジン**。2ページ目を作る |
| 横串 | 探査記録（端末内に記録） | — | 層2と層3を最後まで回らせる |

### 層2 本編は変えない。末尾だけ足す

段階8-Bの1本道（予想2問 → 山なみ → 論点 → 潜水 → 一次資料クイズ7問 → 地下水脈 →
編集部の横断整理 → 探査記録）はそのまま。**足すのは最後の1画面だけ。**

いまは探査記録で終わって行き止まりになっている。ここに次の3つを置く。

1. **同じ判定の主張を、他のテーマで見る** → 資料館へ（例:「裏が取れなかった主張」9件）
2. **別のテーマで同じことが起きているか** → 別テーマの山なみへ
3. **このテーマの一次資料をそのまま読む** → 出典一覧へ

### 層3 横断ページ（新設は2本だけ）

**A. 資料館 —「その主張、資料に当たるとどうなる」**

7テーマ48主張を1ページに並べる。テーマページのクイズ7問を解いた人の受け皿。

- 材料: `data/public/themes/*.json` の `claim_verification`。**追加取材ゼロで作れる**
- 内訳（実データ）: そのとおり21・少しずれる18・裏が取れない9
- テーマ別: 憲法10・自転車7・部活7・高齢者7・消費税6・皇室6・副首都5
  （生成AI・辺野古・あだ名禁止は照合が未実施で0）
- 独自性: 集計では絶対に出てこない。AdSenseの不承認理由「有用性の低いコンテンツ」への
  直接の反証材料になる
- 生成: 公開JSONから機械生成する。**手書きHTMLを `docs/` に置かない**（課題47と同じ事故になる）

**B. 共有している前提 —「立場が違う人が、同じことを心配している場所」**

会社の存在意義そのもので、読後感がいちばん良く、シェアされやすい。
ただし**いま材料があるのは部活動の1テーマだけ**（`editorial_summary` 5件・`veins` 2本。
他9テーマの公開データは0件）。残りは段階10で作ることになる。

**推奨: Aだけ先に作る。**Bは段階10と同時。理由は、Aは48件で最初から読み応えがあるのに対し、
Bは1テーマ分では薄く、AdSenseの「有用性が低い」判定を自分から踏みに行くことになるため。

### 横串 探査記録をサイト全体へ広げる

いまはページ内22地点。これを**10テーマ通しの記録**にする（端末の中だけに保存し、
サーバーには送らない。いまの実装と同じ）。「部活動 22/22・消費税 0/18 …」。
**2ページ目を生む唯一の仕掛け**で、コストは低い。

### 記事（課題51）の置き場所

`docs/articles/{slug}.html`。**記事の中で完結させない。**末尾は必ず該当テーマの
「予想2問」へ送る。記事は検索の入口専用にして、滞在は本編で稼ぐ。

## URLは変えない（構成上いちばん重要な判断）

`/themes/bukatsu-chiiki/` のような階層にしたくなるが、**やらないほうがいい。**

公開はGitHub Pagesで、**サイトの中のパス変更に本物の301転送（恒久的な引っ越し通知）を出せない**。
いま効いている301は「旧ドメイン → 新ドメイン、パスはそのまま」というリポジトリの設定によるもので、
自分でパスを変えたときには使えない。代わりに古いURLへ転送用の中身の無いページを残すことになり、

1. 検索の評価が弱くなる（meta refreshは301より弱い）
2. **中身の薄いページが11本増える**。AdSense審査にいちばん悪い

**結論**: 既存の `{slug}-reaction-map.html` はそのまま。新しいページはフラットに足す。
記事だけは既存URLが無いので `articles/` の下で始めてよい（転送の問題が起きない）。

| | いま（旧2D） | 山なみ1本（段階8-B） | ＋この構成 |
|---|---|---|---|
| ざっと見る人 | 30秒〜1分 | 1〜2分 | 1〜2分（**変わらない**） |

| 全部やる人 | 3分 | 10〜13分 | **15分以上** |

**「ざっと見る人」は伸びない。**ここは仕掛けでは動かない。伸びるのは既に触っている人だけ。
1訪問のページ数は、いまの4.146（週11人・母数が小さい）を当てにせず、
**実数で2ページ目に進んだ人の割合**を新しく測る。

## やらないほうがいいこと

1. **論点ごとに別ページへ分ける**（`/bukatsu-chiiki/kyoin.html` など）。
   1論点あたりの中身が薄く、AdSenseの不承認理由に直撃する。論点は本編の中のパネルのままにする
2. **更新履歴ページを作る**。薄いページが1本増えるだけ。「前回からの変化」はテーマページの中に置く
3. **用語集を1語1ページにする**。作るなら1ページに集約する
   （材料が公開データに無く、書き下ろしが必要。優先度は低い）

## 順番（2026-09-05 オーナー決定）

**段階9の承認 → 段階10（残り9テーマの作り替え）→ 横断ページ。**

AI側は「資料館を1〜2セッションで先に作る」を推していたが、オーナーの判断で後ろへ回した。
**判断が正しい。**理由は3つで、うち2つはAI側が提案時に言い足りていなかった。

1. **行き先が古いままでは効かない。**横断ページは「読み終わった人を別テーマへ戻す」ための
   ものなので、戻した先が旧2Dなら結局そこで帰られる。廊下だけ作っても意味がない
   （提案の「先に決めておくこと2」で自分で挙げた条件そのもの）
2. **後に作るほうが中身が増える。**生成AI・辺野古・あだ名禁止の3テーマは一次資料照合が
   未実施で、いま資料館を作ると48件。段階10にはこの3テーマの段階3（照合）が含まれるので、
   完了後なら**65件前後**になる
3. **急ぐ理由が無い。**資料館のAdSense上の役割は再申請（段階12）の材料で、再申請は
   段階10・11の後と決まっている。先に作っても後に作っても申請には間に合う

**したがって工程表は変えない。**横断ページは段階10の完了後、段階11（総合監査）より前に
1本挿す形にする。
