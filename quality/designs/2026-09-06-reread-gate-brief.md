# 課題62: 読み直しの検査を直す（別セッション用の指示文）

この1枚だけで作業できる。**他の文書を読む必要はない。**
コードを直す作業で、投稿を読む作業ではない。

## 何を直すか

公開の可否を決める独自性の検査に、**下限のつもりが上限として働いている条件**がある。

`scripts/build_planet_data.py` の `independence_gate`：

```python
# 3. 読み直し済みの論点でも、未読の残りが多すぎないこと
for i in data["issues"]:
    s = i["sub"]
    if s["status"] == "reread" and s["unread_count"] > 0.4 * i["count"]:
        ng.append(f"「{i['label']}」の未読が{s['unread_count']}件（全{i['count']}件の4割超）")
```

**「6割以上は読め」のつもりが、「6割読めば終わってよい」になっている。**
部活動の実測で、費用・家庭負担が未読38.5%、受け皿・指導者が39.0%と、
**4割の線の内側ぎりぎりで止まっていた**（偶然こうはならない）。

## 残すべき部分

**4割の余裕そのものは要る。**データは毎月増えるので、全件読み切っても次の収集で
必ず未読が生まれる。100%を求めると収集のたびに公開が止まる。

問題は、いまの検査が**引き算しかしていない**こと。次の2つを区別できない。

- **読み飛ばし** — 読み直した時点で既にあったのに、読まなかった投稿
- **読了後に増えた分** — 読み直したあとの収集で入ってきた投稿

## 直す内容

**余裕は「読了後に増えた分」だけに認め、読み飛ばしは0件を求める。**

| 状態 | いま | 直したあと |
|---|---|---|
| 全部読んだ。その後増えた分が未読 | 通る | **通る** |
| 4割残したまま終わりにした | **通ってしまう** | **落ちる** |

### 判定に使うもの（すでにある）

- 読み直しファイルの `read_at`（例 `data/bukatsu-chiiki_teacher-reread.json`）
- 正典の各投稿の `fetched_at`（例 `social-samples/bukatsu-chiiki_hermes_classified.json`）

`fetched_at <= read_at` の未読 ＝ **読み飛ばし**。それより後 ＝ **増えた分**。

### 注意：`read_at` の書式が揃っていない

部活動の教員ファイルは、別セッションの追記で
`"2026-08-24 / 2026-09-06（追記）"` という形になっている。
**日付を1つだけ取り出せる前提で書くと落ちる。** 書式を整えるか、
文字列から日付をすべて拾って最も新しいものを使うか、どちらかにする。
**整える場合は、既存の読み直しファイル3本すべてを直すこと**
（`bukatsu-chiiki_teacher-reread.json` / `bukatsu-chiiki_cost-receiver-reread.json` /
`bukatsu-chiiki_plan-child-reread.json`）。

## 直す場所の見当

- `scripts/build_planet_data.py`
  - 論点ごとの `sub` を組み立てているところ（`unread_count` を計算している付近）で、
    未読を2種類に分ける
  - `independence_gate` の条件3を、読み飛ばし0件＋増えた分は4割まで、に変える
  - **不合格のメッセージに、どちらで落ちたのかを書く。**
    「読み飛ばしが◯件ある」と「増えた分が4割を超えた」は対処が違う

## 公開への影響（先に知っておくこと）

**この変更を入れると、部活動は当面公開できなくなる。**いまは検査を通っているが、
教員の働き方の**読み飛ばし54件**が引っかかる。54件を読めば通る。

費用・家庭負担（読み飛ばし0・増えた分45）と受け皿・指導者（0・64）は影響を受けない。

**これはオーナーが承知のうえでの変更なので、落ちること自体は想定どおり。**
勝手に条件をゆるめて通さないこと。

## 検査の追加（これが本体）

**コードを直すだけでは、次のセッションが同じことをする。**
このプロジェクトは「指示文の禁止事項は別セッションで破られる。検査だけが残る」を
何度も経験している。**必ずテストを足すこと。**

`tests/` に次を確かめるテストを新設する。

1. 読み飛ばしが1件でもあれば不合格になること
2. 読了後に増えた分だけなら、4割まで合格すること
3. 増えた分が4割を超えたら不合格になること
4. `read_at` が `"2026-08-24 / 2026-09-06（追記）"` のような形でも落ちないこと

## 完了の確かめ方

```bash
python3 -m unittest discover -s tests
python3 scripts/build_planet_data.py --topic bukatsu-chiiki
```

成功の形:
- テストが `OK`
- 部活動は**「教員の働き方に読み飛ばしが54件ある」という主旨で不合格になる**
  （通ってしまったら、直せていない）

そのうえで、影響を受けないことの確認として、費用・家庭負担と受け皿・指導者が
このメッセージに出てこないことも見ること。

## やってはいけないこと

- **4割の余裕を無くさない。**収集のたびに公開が止まる
- **部活動を通すために条件をゆるめない。**落ちるのが正しい姿
- **テストを書かずに終わらせない。**検査にしないと守られない
- **共有ツリーで作業しない。**`git worktree add ../isa-wt-<名前> -b task/<名前> main`
