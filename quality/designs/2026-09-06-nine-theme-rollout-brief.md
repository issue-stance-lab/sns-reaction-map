# 課題54 段階10: 残り9テーマへの展開（別セッション用の指示文）

この1枚で全体像がつかめるように書いてある。作業に入る前に**「最初に読むこと」だけは
必ず読むこと**。読まずに始めると、コードを書いてから前提が崩れる。

## 最初に読むこと（ここが結論）

**この作業の大半はコードではなく、投稿を人が読む作業になる。**

生成器 `scripts/build_planet_data.py` は、公開ページを出す条件として
**「編集部が本文を読み直した論点が、意見全体の50%以上を占めること」**を要求する
（`independence_gate`）。さらに読み直した論点ごとに**未読が4割を超えないこと**も要る。

9テーマでこれを満たすために読む必要のある投稿は、**ざっと3,400件**（下の表を参照）。
1テーマあたりの設定ファイルづくりやページ生成は半日で終わるが、**読む作業はそれとは
桁が違う**。

**だから「9テーマを順に全部やる」計画は立てないほうがいい。**進め方は下の「進める順番」を見ること。

## いまの到達点

- **見本は部活動の地域移行**。`quality/prototypes/bukatsu-chiiki-page-preview.html`
  （生成は `python3 scripts/build_planet_page_preview.py`）
- ページの形：**第1部 何が、どこまで進んでいるのか** → 学校の外へ出した後だれが続けるか
  → **SNS反応マップ** → 論点ごとに、なかを見る → 投票 → このページの作り方 → 次に見るテーマ → 詳細データ
- 部活動は**公開できる状態ではない**。独自性の検査で止まっている
  （`quality/designs/2026-09-06-stage9a-reread-brief.md` が別に走っている）

## いちばんの壁：ページの構造がテーマごとに違う

いまのアダプタ `scripts/build_planet_page_preview.py` は、**公開ページから決まった区間を
文字列で探して切り取り、そこへ差し込む**作りになっている。ところが10テーマの
ページは、共通の目印が7つしかなく、中身の区間はばらばらだった（実測）。

| 目印 | ある テーマ数 |
|---|---|
| ADSENSE_TAG / ARTICLE_JSON_LD / ARTICLE_TRUST / GA_TAG / RESEARCH_CONDITIONS / SEO_META / TIDE_CARD | **10（全部）** |
| BACKGROUND_SOURCES | 6 |
| ARGUMENTS | 4 |
| CLAIM_AUDIT | 2 |
| DETAIL_TABLES / INSIGHT_STATS | 2 |
| PROCESS_SECTIONS / REREAD_BASIS / VERIFY_SECTION / FACT_CHECK / ISSUE_VOICES / STANCE_SUMMARY / KOSHITSU_AUDIT / THEME_ATLAS / BUKATSU_ENTRY | 各1 |

**つまり、いまのアダプタは部活動でしか動かない。**差し込み位置に使っている
`<!-- BUKATSU_ENTRY_END -->` は他の9テーマに存在しない。

### どう直すか（2案）

- **案A（推奨）: 組み立て型に作り替える。**「切り取る」のをやめ、
  **残すものを名指しして、それ以外の `<main>` の中身を捨てる**。
  残すのは全テーマ共通の7つの目印の区間＋投票＋関連テーマ＋詳細データ＋投稿サンプル。
  テーマごとの設定は「残すものの一覧」だけになり、10テーマで同じコードが動く
- **案B: テーマごとに切り取る区間の一覧を持つ。**いまの延長で、設定を10本書く。
  最初の1〜2テーマは速いが、テーマが増えるほど壊れやすい

**案Aを推す。**理由は、いま切り取っている区間名（`7つの論点とXの声` など）が
他テーマには存在せず、案Bだと結局10通りの一覧を人が読んで作ることになるため。

## テーマ1本に必要なもの

| 要るもの | 置き場所 | 部活動での実例 | 9テーマの状況 |
|---|---|---|---|
| 論点・立場の設定 | `configs/planet/{テーマ}.yaml` | あり | **9本とも無い** |
| 経緯・背景の台帳 | `data/verification/{テーマ}-background.json` | あり | **9本とも無い**（`quality/research/{テーマ}-primary-sources.md` が10テーマ分そろっているので、そこから書ける） |
| 一次資料の照合 | 公開JSONの `claim_verification` | 7件 | 6テーマにあり／**生成AI・辺野古・あだ名禁止は0件**（段階3から） |
| 資料にあるのにSNSにないこと | `data/verification/{テーマ}-sunk-continents.json` / `-veins.json` | 4件／2本 | **9テーマとも無い** |
| 編集部の横断整理 | `data/verification/{テーマ}-editorial.json` | 5件 | **9テーマとも無い** |
| 論点の読み直し | `data/{テーマ}_*-reread.json` | 3本 | 自転車に2本、他は無い |

## 読む量（実測）

「要読了」は、独自性の検査（意見の50%以上）を満たすために**読み直し済みにする必要のある
論点の合計件数**。実際に本文を読む数は、その6割前後（各論点で未読を4割以下に抑えるため）。

| テーマ | 意見数 | 一次資料の照合 | 要読了(50%) |
|---|---|---|---|
| 消費税減税 | 3,358 | 6 | 1,679 |
| 生成AIと著作権 | 2,593 | **0** | 1,297 |
| 副首都構想 | 1,453 | 5 | 727 |
| 憲法改正 | 1,372 | 10 | 686 |
| 皇室典範改正 | 1,282 | 6 | 641 |
| 自転車の青切符 | 468 | 7 | 234 |
| 高齢者の免許返納 | 353 | 7 | 177 |
| 辺野古の事故 | 341 | **0** | 171 |
| あだ名禁止 | 93 | **0** | 47 |
| **合計** | | | **5,659** |

**この表は既存の読み直しを数えていない。**1本目の自転車を実測したところ、過去に350件を読み直してあり、**残りは26件（最少4件）**だった（要読了234件ではない）。
テーマごとに、まず既存の読み直しデータを数えること。読み直しファイルがあるのは
**部活動と自転車だけ**なので、他の7テーマは表のとおりの規模になる見込み。

## 進める順番（推奨）

**小さいテーマから2〜3本やって、仕組みを確かめてから大きいテーマへ行く。**

1. **自転車の青切符** — 一次資料の照合7件と読み直しが2本すでにある。**最初の1本はこれ**
2. **高齢者の免許返納**（照合7・177件）
3. **あだ名禁止**（47件と最小。ただし照合0なので段階3から）

ここまでで、案Aの作り替えが10テーマで通用するかが分かる。**4本目以降は、
実際にかかった時間を測ってからオーナーに相談すること。**消費税（1,679件）を
勢いで始めない。

## 1テーマの手順

1. 専用の作業ツリーを作る。`git worktree add ../isa-wt-<名前> -b task/<名前> main`
2. `social-samples/` を共有ツリーから同期する（gitに入らないため）
   `rsync -a ../issue-stance-aggregator/social-samples/ social-samples/`
3. `configs/planet/{テーマ}.yaml` を書く（部活動のものを写して直す。**件数は書かない**）
4. `data/verification/{テーマ}-background.json` を書く
   （`quality/research/{テーマ}-primary-sources.md` を読み、定義1文・なぜ始まったか・
   経緯の年表・確かめること。**すべて出典URL付き**。件数は書かない）
5. 論点の読み直しを行い、`data/{テーマ}_*-reread.json` を作る
   （やり方は `quality/designs/2026-09-06-stage9a-reread-brief.md` と同じ）
6. `python3 scripts/build_planet_data.py --topic {テーマ}` が**検査に落ちずに**通ることを確認
7. アダプタでページを組み立て、実画面で見る

## 通す検査

```bash
python3 scripts/build_planet_data.py --topic {テーマ}   # --prototype を付けない
python3 -m unittest discover -s tests
python3 scripts/verify_theme_page.py
python3 scripts/verify_number_provenance.py
python3 scripts/verify_top_page.py
```

成功の形: 検査不合格が出ない／`OK`／`NG 0件`。

**同じ入力で2回生成して差分が出ないこと**も毎回確かめる（課題34）。

## やってはいけないこと

- **`--prototype` で独自性の検査を迂回しない。**公開できないページができるだけ
- **設定ファイルに件数を書かない。**件数は必ず正典から数え直す
- **手書きのHTMLを `docs/` へ置かない。**`verify_builder_rebuildability.py` が落ちる
- **共有ツリーで作業しない。**専用の作業ツリーを作る
- **9テーマを一度に始めない。**1本ずつ、検査を通してから次へ
- **`verify_theme_page.py` が旧ページの形を前提にしている。**新しい形へ変える作業が
  別途要る（部活動でも未解決）。ここに気づかず「検査が落ちるから中身を戻す」をしないこと
