# 「議論の惑星」をAdSense審査で不利にしないための対策

作成日: 2026-08-30
状態: 提案。CEO判断待ち
上位正典: `quality/designs/reaction-planet-renewal.md`（課題54）／`TASK_BOARD.md` 課題15

## 1. 結論

**惑星そのものはAdSenseの不承認理由に答えていない。** 3回目の不承認理由は
「有用性の低いコンテンツ」で、2026-08-16の診断でNGだったのは Experience（著者が実際に
調査・検証した過程が本文にない）だった。表示の作り込みは、いくら増やしてもこの反証にならない。

さらに悪いことに、**惑星は今OK判定だったものを壊しかねない。** 同じ診断で
「自動生成コンテンツの疑い」がOKだった根拠は「定型的な繰り返しがなく、論点ごとに異なる構造」。
1つの生成器で10テーマを作ることは、この根拠をいちばん壊しやすいやり方である。

したがって、惑星を10テーマへ広げること自体が対策ではない。**惑星を「調べた記録を置く場所」
として使い、記録が無いテーマは機械的に公開させない**ことが対策になる。

この状態で10テーマに惑星を並べると、8テーマは島が「まだ読み直していない分」だけになり、
4テーマは一次資料が無い。**同じ形の薄いページが10本並ぶ**という、審査でいちばん不利な形になる。

## 3. 対策

### 対策1: 生成器自身に独自性の検査を持たせた（実装済み）

`scripts/build_planet_data.py` に `independence_gate()` を入れた。次のどれかに当てはまると、
公開用ページを**出力しない**（終了コード1）。

1. `data/{テーマ}_claim_posts.json`（一次資料との突き合わせ）が無い
2. 編集部が読み直した論点が、意見全体の50%未満
3. 読み直し済みの論点でも、未読が全体の4割を超えている
4. テーマ固有の「中心の問い」が設定されていない

試作として作るときは `--prototype` を付ける。その場合はページ冒頭に
「このページは公開できません」と落ちた理由が表示される。

指示文に書いた禁止は別セッションで破られてきた（2026-08-18の見出し完全一致）。
**検査だけが残る。** だから文章の約束ではなくコードで止める。

現に部活地域移行はこの検査に落ちる。落ちることが正しい。

### 対策2: 共通化してよい範囲を線で引く

| 共通にする | テーマごとに必ず変える |
|---|---|
| データの形式、面積・色・標高の計算式 | 中心の問い、論点名、論点の境界 |
| 3Dの操作、キーボード操作、フォールバック | 島の区分名（人が読んで付けた名前） |
| 凡例、サンプル注意書き、調査方法の枠 | 代表的な理由、一次資料、編集部の整理 |
| 検査スクリプト | 何を確かめて何が確かめられなかったか |

島の区分名は、編集部が投稿を1件ずつ読んで付けた言葉である。生成器では作れない。
**ここがテーマごとの違いを自動的に生む。** 逆に言えば、読み直しをしていないテーマは
どうやっても他テーマと同じ形になる。

### 対策3: 一次資料を「論点ごと」に置く

いまの一次資料セクションは1ページに1つの表として置いてある。惑星では、
**着陸した論点の中だけに、その論点に関係する一次資料と確認結果を出せる。**

- 「費用・家庭負担」に降りたら、月額の実額とスポーツ庁の資料
- 「受け皿・指導者」に降りたら、指導者報酬の公表資料

同じ資料を全ページに貼るのではなく、論点ごとに分けて置くことになるので、
形をコピーしにくくなる。既存の `FACT_CHECK_GUIDE.md` の工程はそのまま使える。

### 対策4: 「どこまで人が読んだか」を出すこと自体が独自価値

灰色の「まだ読み直していない分」の島は、隠すべき弱点ではなく**出すべき情報**である。

- 誰が・いつ・何件を読んだかが、論点ごとに数字で出る
- AIが自動で付けた区分と、人が読んで付けた区分を同じ見た目にしない
- 読み直しが進むと灰色の島が縮む（作業の進み方がそのまま画面に出る）

自動生成のサイトは、この情報を出せない。出す理由が無いからである。

### 対策5: `verify_page_originality.py` を惑星ページへ接続する（未実装）

既存の重複検査は現行のテーマページを対象にしている。惑星ページの
着陸パネル本文を検査対象に加え、凡例・注意書き・調査方法の枠は
`configs/page-originality.json` の `shared_selectors` へ理由つきで登録する。

**これを先にやる。** 検査に接続する前に10テーマを生成すると、
似た文章が10本できてから気づくことになる。

## 4. 展開の順番の変更提案

上位設計は「部活で基準実装 → 残り9テーマへ展開 → 10テーマ同時公開 → 再申請」としている。
中身の実測を踏まえ、次のように変えることを提案する。

1. 課題15-A（数字・用語・2リポジトリの整合）を完了する — **これは変えない。前提**
2. 対策5（重複検査の接続）を実装する
3. 部活地域移行に一次資料の突き合わせを実装し、教員の働き方の賛成側136件を読み直す
   （＝独自性の検査を実際に通す）
4. 部活を非公開の基準実装として完成させ、CEOが共通仕様を承認する
5. **一次資料と読み直しがそろったテーマから順に惑星化する。** 検査に落ちるテーマは
   惑星にせず、現行ページのまま残す
6. 惑星化できたテーマが増えてから、10テーマ総合監査 → 同時公開 → 再クロール確認 → 再申請

つまり「全テーマを惑星にしてから公開」ではなく、「中身がそろったテーマだけ惑星にする」。
薄いテーマを見た目で埋めないことが、今回の審査対策の中心になる。

## 5. 確かなことと、確かでないこと

- 確か: 惑星だけでは不承認理由に答えていない。一次資料と読み直しは、いま8割のテーマで足りない
- 確か: 生成器の検査は動いており、部活は現に落ちる
- **確かでない: これでAdSenseが通るかどうかは分からない。** 不承認理由は
  「有用性の低いコンテンツ」という一般的な文言で、どこが基準を割ったかは開示されない
- 対策5は未実装。10テーマ展開の前に必要
