## 3. データの接続と照合（手書きの件数ゼロ）

| 表示 | 出所 | 止まる条件 |
|---|---|---|
| 論点の件数・割合・順位 | 公開JSON `issues[].count`・`opinion_count` | 論点の合計≠意見数 |
| 立場の帯・立場別集計 | 公開JSON `issues[].stances` | 立場の合計≠論点の件数、立場の種類が planet 設定と違う |
| 理由区分の件数 | 再読データ `buckets[論点名]` を明細 `items[].bucket` で数え直す | 区分の合計・明細の件数≠論点の件数、区分の件数≠明細 |
| 区分ごとの立場・投稿の立場 | 立場の対応表（post_key → 正典の立場） | 明細と対応表の投稿が一致しない、論点×立場の合計≠公開JSON |
| 主張の照合 | 公開JSON `claim_verification`＋`data/verification/constitutional-amendment-claims.json` | 該当投稿数が照合データと違う、知らない判定 |
| 資料にしかない話 | 公開JSON `ocean_layer.sunk_continents` | 母数≠意見数、論点が null で設定 `sunk_issue_overrides` にも無い |
| 共通する心配 | 公開JSON `ocean_layer.veins` | 論点・立場名が公開JSON・planet 設定に無い |
| 制度の確認 | 背景台帳 `checklist.items`（`issue_ids`） | 注記の先がこの論点に無い |
| 条文の確認日 | 一次資料メモの節の「確認日」 | 見出しが1件でない、確認日が無い |

**再読データの立場のずれ**：再読データの明細には立場（stance）が無かったため、ずれを直接見ることはできなかった。
`scripts/constitutional_reread_stances.py` で正典（`classification.stance`）から1,963件の立場を写し、論点×立場（7×4）を数えると公開JSONと**全セル一致（ずれ0件）**。
明細1,963件はすべて正典にあり、正典でも意見・同じ論点だった。共有の再読データ・台帳（`data/verification/reread/constitutional-amendment.json`）は変えていない。

**資料にしかない話の振り分け**：公開JSONで論点が null の2件を設定で置いた。国民投票の結果への異議（第127条）→国民投票・広告、参議院の緊急集会の措置のその後→緊急事態条項。

## 4. 冒頭の変更（確認日と時制）

- 確認日を設定の `checked_on`（2026-10-12）1か所にした。「いまの段階」の確認日と FAQ の「◯月◯日時点」はここから作る（前は背景台帳の 2026-09-13）。背景台帳より古い日付は止まる。
- 国民投票法の改正（令和8年法律第73号、施行 2026-10-31）を副首都と同じ3段階にした。基準日（`--as-of`、既定は公開JSONの更新日）が施行日より前なら「施行される予定です」、過ぎて `law.enforcement_confirmed_on` が null なら「施行される予定でした。施行後の条文は編集部で確かめていません」、確認日を入れると「施行されました（◯日に条文を確認）」。
- 短答の2文目「直近の通常国会では…」を「前の国会（第221回）では、憲法審査会で…」に直した。第221回国会は特別会（衆参のページの表記）。
- FAQ「改正は0回」に、e-Gov の改正履歴が施行時の版だけである旨と確認日を足した。
- 出典の確認日を更新し、衆参の憲法審査会のページを出典に足した。一次資料メモ【2026-10-12追記】。
