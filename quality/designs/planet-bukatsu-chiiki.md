## 3. 面積の式

```
raw_i   = 件数_i / 993 * 100
area_i  = max(raw_i, 2.5)                    # 最小面積の床
超過分は床に達していない大陸から、面積比で按分して差し引く
```

- 床を2.5%にする理由: 地域格差は9件（0.9%）で、比例のままだと球面上でクリックも視認もできない。
- 床を使った大陸には凡例と着陸パネルに「面積は最小表示に拡大しています。実件数は9件」と明示する。
- 面積が実比率と一致しない大陸が1つでもある回は、凡例の注記を機械的に出す（手書きしない）。

## 4. 色

赤=反対／青=賛成は使わない。4立場に固有色を割り当て、色相・明度の両方で区別する。

| 立場 | 色 | 明度の目安 |
|---|---|---|
| 移行支持 | ティール `#2F8F83` | 中 |
| 慎重・反対 | 紫 `#7D5BA6` | 暗 |
| 条件付き・改善要求 | 黄土 `#D9A520` | 明 |
| 中立・情報 | 灰 `#8B9199` | 中（低彩度） |

大陸の色 = 最多立場の色。彩度 = その立場の占有率（純度）を 40%〜100% へ写す。
純度が低い大陸ほど白っぽくなり、「割れている論点」だと色だけで分かる。

色は要約でしかないので、**着陸パネルには必ず4立場すべての分割帯と実件数を出す**。
色覚特性に依存しないよう、分割帯には立場名のラベルを直接置く。

## 5. 標高

標高は「強い表現（intensity=high）の投稿が占める割合」だけを表す。正しさ・重要度・支持率ではない。

```
p0 = 0.219                      # 993件全体の high 率
k  = 50                         # 小標本の抑制係数
p_i = (high_i + k * p0) / (件数_i + k)
標高_i = 4.00 * p_i / max(p)    # 半径に対する % 、上限4%
```

- 地域格差の high 実測は66.7%だが n=9。抑制後28.7%に収まり、他の大陸と極端な差にならない。
- 標高は面積と独立。投稿数は面積で表しているので二重計上しない。
- この式が他テーマで再現できない場合は、上位設計どおり**標高を0にして公開する**。
  見た目のために推測値を入れない。

## 6. 固定するもの

- `issue_id` は既存ページのカウンタIDを引き継ぐ（`bukatsu-chiiki-kyoin` など）。
  URLアンカーも同じ文字列にし、note・Xからの直リンクを壊さない。
- **投票の論点の並び順は現行のまま変えない。** 投票は論点の番号で保存されており、
  並べ替えると過去の投票の意味が変わる。現行順は
  費用・家庭負担 / 受け皿・指導者 / 教員の働き方 / 教育的意義・機会 / 地域格差 /
  制度・移行プロセス / その他・わからない の7つ。
  惑星の**表示順（件数順）と投票の保存順は別物として扱う**。
- 大陸の座標と形状seedは `issue_id` から決定的に導く。更新で件数が変わっても大陸は移動しない。
  位置は見やすさのための配置であり、論点同士の近さを意味しないと凡例に書く。

### 着陸パネルに入れるもの（論点ごと）

- 件数と母数（例: 283件 / 意見993件中28.5%）
- 4立場の分割帯と実件数
- 中心の問い、含める／含めない境界
- 代表的な理由（立場ごと。賛否の機械的な鏡像にしない）
- その立場が守ろうとしている価値
- 一次資料へのリンク
- まだ分かっていないこと
- 表現の強さの値と定義へのリンク

### 横断整理（惑星全体）

現行データから言える横断的な発見を、編集部の文章として置く。例として次を検討する
（実装時に本文を確定する。ここでは論点の切り口だけを決める）。

- 「教員の働き方」では移行支持が58%と多いが、「教育的意義・機会」では慎重・反対が49%で逆転する。
  同じ人が反対しているのではなく、**論点が変わると賛否が入れ替わる**構造である。
- 「費用・家庭負担」は慎重・反対47%＋条件付き31%で、無条件の支持が18件しかない。
  お金の話になると賛成側も条件を付ける。
- 「地域格差」は9件しかないが、そのうち8件が慎重・反対。件数が少ない＝重要でない、ではない。
  収集した投稿の中で語られていないだけであることを明記する。

## 8. 3Dが使えない場合

初期HTMLに7論点の名前・件数・比率・4立場内訳・要旨・一次資料リンクを持たせる。
WebGL失敗、JavaScript無効、キーボード操作のいずれでも同じ内容へ到達できる。
惑星は拡張表示であって、HTMLの代わりではない。

- 生成器の出力と第2節の表（件数・面積・色・標高）が完全一致する

- 公開本文にAIの信頼度・分類理由・内部指示が出ていない

## 10.5 着陸アニメーションの案

### 前提（どの案でも守る）

- **本文はアニメーションを待たない。** 大陸を押した瞬間（0ms）に着陸パネルのHTMLをDOMへ入れ、
  URLハッシュを更新し、見出しへフォーカスを移す。動きは後から追いつく飾りであって、内容の門番にしない。
- 端末の「視差効果を減らす」設定がONなら、全アニメーションを飛ばして即座に着陸状態にする。
- 戻る操作は「全体へ戻る」ボタン、Escape、ブラウザバックの3つすべてで効く。
- 自動回転はしない。ユーザーが触っていないときは描画も止める。

### 案A: 惑星を回して降りる（推奨）

| 時間 | 起きること |
|---|---|
| 0ms | 着陸パネルのHTMLが出る。フォーカス移動。URL更新 |
| 0–350ms | **球が自転して**選んだ大陸を正面へ持ってくる（カメラは動かさない） |
| 250–700ms | カメラが寄る。同時に他の大陸の彩度を25%まで落とす |
| 700–900ms | 大陸の輪郭が光り、下位の島が浮き上がる（10.6節） |
| 戻り | 600msで逆再生。選んでいた大陸のボタンへフォーカスを戻す |

カメラではなく球を回すのが要点です。カメラを振り回すと画面酔いが起きやすく、
「今どこを見ているのか」も分からなくなります。地球儀を手で回す感覚に寄せます。

### 案B: 大陸を切り出して手前に浮かせる

惑星が半透明になり、選んだ大陸だけがブロックとして手前へ抜き出される。断面に立場の層が見える。

- 良い点: 「この論点だけを取り出して見ている」ことが直感的。断面と10.7節の地層表現が噛み合う
- 悪い点: 球から離れるので全体の中の位置を見失う。実装が重く、端末を選ぶ

### 案C: 回転とズームだけ

演出を足さない。350msで正面へ回し、ズームして終わり。

- 良い点: 一番速く、一番壊れない。低スペック端末でも確実
- 悪い点: 「降りた」感じがなく、ただの拡大に見える

### 私ならこれ

**案A。** 案Bは見せ場としては強いのですが、初版で球から離れる表現をやると、
「大陸の位置には意味がない」という前提が崩れて見えます。案Cは安全すぎて、
今回のリニューアルの目的（惑星を中心商品にする）に届きません。

案Aを作ったうえで、低スペック端末と「動きを減らす」設定では自動的に案C相当へ落ちる、
という二段構えにします。案Bは、初版が動いてから次版で検討します。

### 案A: 大陸が島に割れる（推奨）

着陸すると大陸の輪郭が割れ、下位区分ごとの島になる。島の面積＝その区分の件数。
島を押すと、その区分の代表的な理由と投稿が出る。

- 良い点: 「大陸＝論点、島＝具体的な言い分」という入れ子が一目で通る。
  面積のルール（件数）が階層をまたいで同じなので、説明が増えない
- 悪い点: 下位区分があるのは3大陸だけ。残り4大陸は割れない

### 案B: 着陸したら2Dの区分図に切り替える

3Dは大陸まで。着陸後はその論点だけの平面図（帯やツリーマップ）にする。

- 良い点: 面積の比較が正確になる。実装が軽い。3Dが動かない端末との差が小さい
- 悪い点: 着陸のたびに表現が3D→2Dへ切り替わり、体験が途切れる

### 案C: 3Dは大陸まで。下位はHTMLの一覧だけ

- 良い点: 一番安全で、一番早く出せる
- 悪い点: 「具体的な論点をどう見せるか」という今回の問いに答えていない

### 私ならこれ

**案A。ただし「割れる大陸と割れない大陸がある」ことを隠さない。**

これは弱点ではなく、むしろ出すべき情報だと考えます。
割れない大陸には「この論点は、まだ編集部が1件ずつ読み直していません」と表示します。
AIが自動で作った下位区分と、人が読んで作った下位区分を、同じ見た目で並べないためです。
どこまで人の手が入っているかが読者に分かることは、AdSenseが求める独自性の証拠にもなります。

### 実装前に必ずやること（重要）

再読データは**古いスナップショットのもの**です。当時と現在で件数が違います。

| 論点 | 再読した時点 | 現在（8/27） | 未読 |
|---|---:|---:|---:|
| 教員の働き方 | 227件中87件（支持以外のみ） | 283 | 支持側136件＋増分56件 |
| 費用・家庭負担 | 72 | 97 | 25 |
| 受け皿・指導者 | 100 | 143 | 43 |

差分を読み直さずに島を出すと、島の合計と大陸の件数が合いません。
また教員の働き方は移行支持側が未再読なので、**初版で島にするのは費用・家庭負担と受け皿・指導者の2大陸だけ**に
します。教員は支持側136件を読み直してから島にします。

### 次版で検討すること（初版ではやらない）

「送迎・移動」は費用（9件）と受け皿（2件）の両方に出てきます。論点をまたぐ小さな主題です。
将来は大陸間の「海峡」として表現できますが、初版では大陸の位置に意味を持たせない方針なので見送ります。

## 10.7 賛成・反対の表現の案

現行データは 移行支持414 / 慎重・反対329 / 条件付き・改善要求206 / 中立・情報44 です。
**条件付き206件をどちらにも寄せない**ことが、このテーマで一番大事な設計判断になります。

### 案A: 大陸の色＝最多の立場、着陸したら4立場の帯（構想の既定）

- 良い点: 全体を一目で把握でき、詳細は着陸後に正確に出る
- 悪い点: 「最多」しか色に出ないので、僅差の大陸が塗りつぶされて見える

### 案B: 地層の断面

島を押すと縦の断面が現れ、4立場が地層のように積み重なる。層の厚み＝件数。

- 良い点: 4つの立場を潰さずに全部見せられる。案Bの着陸演出と相性がよい
- 悪い点: 地層＝時間の積み重ねと誤読される恐れがある

### 案C: 立場フィルター＝「見えている世界」の切り替え（強く推奨）

惑星の上に4つの立場ボタンを置く。押すと、**その立場の投稿だけで大陸の大きさを作り直す。**
実データで計算するとこうなります。

| 論点 | 移行支持414件の世界 | 慎重・反対329件の世界 |
|---|---:|---:|
| 教員の働き方 | **164（39.6%）最大** | 57（17.3%） |
| 教育的意義・機会 | 76（18.4%） | **93（28.3%）最大** |
| 制度・移行プロセス | 97（23.4%） | 57（17.3%） |
| 受け皿・指導者 | 39（9.4%） | 57（17.3%） |
| 費用・家庭負担 | 18（4.3%） | 46（14.0%） |
| その他 | 20（4.8%） | 11（3.3%） |
| 地域格差 | **0件（大陸が消える）** | 8（2.4%） |

賛成の人は「先生の働き方」の大陸に立っていて、反対の人は「子どもの教育」の大陸に立っています。
**同じテーマなのに、見ている大陸そのものが違う。** さらに賛成側の世界には「地域格差」の大陸が
存在しません（サンプル中に1件もない）。

これは「どちらが多いか」ではなく「なぜ話がかみ合わないか」を見せる表現で、
会社のPurpose（対立の向こう側にあるもう一つの正義を可視化する）に直接対応します。

- 良い点: 賛否を勝ち負けにせず、視点の違いとして提示できる。既存データだけで今すぐ作れる
- 悪い点: 面積の意味が「全体の件数」から「その立場内の件数」へ変わるので、
  切り替え中は表示を明確に変え（惑星の縁の色、見出しの文言）、母数を必ず併記する必要がある

### 案D: 赤青の二極（南北の極冠など）

**採用しない。** 立場を2つに潰すことになり、条件付き206件の行き場がなくなります。
惑星上の位置に賛否の意味を持たせると、「大陸の位置に意味はない」という前提とも矛盾します。
