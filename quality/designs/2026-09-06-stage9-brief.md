# 課題54 段階9: 性能を測り直し、共通仕様の承認を得る（別セッション用の指示文）

この1枚だけで作業できる。**他の文書を読む必要はない。**

## この作業は何か

**オーナーの出番は課題54全体で3か所しかない。そのうちの1つがこれ。**
工程表に「**判断点。ここだけ必須**」と書かれている。

やることは2つ。

1. **山なみ版で性能を測り直す**（前回の値は無効。理由は下）
2. **オーナーが「この形で残り7テーマも進めてよい」と判断できる材料をそろえる**

**承認が出るまで、残り7テーマへ広げないこと。**あとで仕様を変えると手戻りが10倍になる。

## 前回の実測が無効な理由（2つ）

記録は `quality/reviews/2026-09-05-task54-stage9-measurements.md`（球の版として保存済み）。
LCP 112ms / INP 88ms / CLS 0 という値が載っているが、**そのまま使ってはいけない。**

**理由1: 球のページで測った。**段階8-Bで球を廃止し、横から見た断面図（山なみ）へ
作り替えたので、測った対象がもう存在しない。

**理由2: 広告も計測タグも無いページで測った。**記録自身にこう書いてある。

> ページ全体で **HTTPリクエストは1本だけ**（103KB）。外部CDN・外部フォント・画像を一切読まない

**実際の公開ページは、AdSenseとGA4と画像9枚を読む。**リクエスト1本のページの数字は、
本番の速さの目安にならない。**理由2は前回の記録に書かれていないので、今回は必ず
保護タグを含む版で測ること。**

## 測る対象

見本は3テーマぶんある。**3つとも測る**（1テーマだけだと、テーマ固有の重さと
共通の重さを区別できない）。

```bash
# 保護タグを含む版を出す。--for-docs を付けないとGA4が外れる
for t in bukatsu-chiiki bike-blue-ticket elderly-license-revocation; do
  python3 scripts/build_planet_page_preview.py --topic "$t" --for-docs \
    --out "/tmp/stage9-$t.html"
done
```

成功の形: 3ファイルできて、それぞれに `googletagmanager` と `adsbygoogle` が
1つずつ入っている（`grep -c` で確認する）。

**注意**: この版は計測用。`docs/` へは置かない。GA4が入っているので、
**測定でついた数字が実サイトのアクセス記録に混ざらないよう、配信元とホスト名に注意する。**
混ざる恐れがあるなら、GA4のIDだけ差し替えて測る（差し替えたことを記録に書く）。

## 承認の材料をそろえる

**性能だけでは承認できない。**オーナーが判断するのは「**この形を共通仕様にしてよいか**」。
次を1枚にまとめること。

1. **画面の並び**（何部構成で、何がどの順に出るか）
2. **決めごと**（数字はすべて正典から数え直す／煽らない書き方／
   資料にあるのにSNSにないことの扱い／同じ数字は1ページに1回だけ）
3. **3テーマの見本へのリンク**（実際に触れる状態で）
4. **性能の実測値**（上の表）
5. **できていないこと**を正直に書く（下の「残っている宿題」を参照）

**「承認してください」で終わらせない。**判断に必要なことが伝わらなければ、
作業が正しくても意味がない。

## 残っている宿題（承認の材料に必ず書く）

- **新形式は3テーマとも未公開。**`docs/` は全テーマ旧形式のまま
- **`verify_theme_page.py` が旧ページの形を前提**にしている。新形式へ合わせる作業が別途要る
- 論点カードの上にある「論点の一覧」が、下の論点カードと同じ7つ・同じ件数を並べている
  （図が使えない人の入り口でもあるため、消すかどうかは判断が要る）
- 投票の1問目「あなたが一番気になる論点は？」が、地図と同じ仕事をしている
