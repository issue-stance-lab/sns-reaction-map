## 手順0：分類モデルを `kimi-k2.6` に戻す（最優先）

**2026-09-06、オーナーが `kimi-k2.6` を正と決定した。**

いま `~/.hermes/config.yaml` の `model.default` は **`upstage/solar-pro4:free`**
（2026-09-06 08:18 に更新されていた）。`DATA_REFRESH.md` の記述と食い違っている。

**このまま次の収集を回すと、正典に別モデルの分類が黙って混ざる。**
`DATA_REFRESH.md` 自身が、モデルを替えると**賛否の構成比が最大4ポイント動く**と
実測で記録している（2026-08-18、同一30件で `kimi-k2.6` との一致率は論点77%・賛否73%）。

### 手順

1. **他セッションが分類中でないことを確認する。**

   ```bash
   pgrep -fl "classify_.*hermes|refresh_topic"
   ```

   何も出なければ進む。出たら**終わるまで待つ**。設定を変えた瞬間に他セッションも
   切り替わり、1回の更新の中でモデルが混ざる。

2. **いまの値を記録してから変える。**

   ```bash
   cp ~/.hermes/config.yaml ~/.hermes/config.yaml.bak-$(date +%Y%m%d%H%M)
   grep -n "^model:" -A2 ~/.hermes/config.yaml
   ```

3. **`model.default` を `kimi-k2.6` にする。**

   **識別子の正確な文字列は、変更前に確かめること。**この作業を書いた時点では、
   直前の値を示す証拠（設定のバックアップ・履歴）が残っておらず、
   リポジトリ内の記述は一貫して `kimi-k2.6` という短い形だった。
   いまの値 `upstage/solar-pro4:free` のように提供元の接頭辞が要る形式かもしれない。
   **推測で書き換えて分類が黙って別モデルへ落ちるのが最悪の結果なので、
   分からなければオーナーに正確な文字列を聞く。**

4. **変えたら、小さく1回試して分類が通ることを確かめる。**
   本番の正典へは書かない。通らなければ手順2のバックアップから戻す。

5. **`DATA_REFRESH.md` の記述と実設定が一致していることを確認する。**
   一致していなければ文書側を直す。

**この手順0が終わるまで、収集・分類を回さないこと。**

（`data/verification/bike-blue-ticket-fetch-history-recovery.json`）。**過去の穴は塞がった。**

**収集回ごと：足りないものがある。**

`social-samples/updates/{日付}/report.json` に、回ごとの記録がすでにある。

```
checks / raw / duplicates / new / relevant / opinions / opinion_flag_available /
candidate / classification_errors / status / topic / date / run_id /
queries / taxonomy / timings / next_collect_at
```

**入っていないもの（これを足す）**

| 足すもの | なぜ要るか |
|---|---|
| **分類モデル名** | 手順0の問題そのもの。どの回をどのモデルで分類したか分からない |
| **プロンプト・分類基準の版** | 基準を変えたのか、モデルが変わったのか、世論が動いたのかを区別できない |
| **入力の指紋（生データのsha256）** | 同じ入力から同じ結果が出るかを後で確かめられる |
| **取得元** | 投稿ごとには入っているが、回の単位では残っていない |

### やること

1. **`report.json` に上の4つを足す。**書き手は `scripts/refresh_topic.py`
2. **新しい回でこれらが欠けていたら止める検査を作る。**
   `scripts/` に検査を1本足し、`tests/` にその検査のテストを足す
3. **投稿ごとの必須項目（取得日時・検索語・取得元）が欠けたら止める検査も足す。**
   自転車の116件は「欠けたまま通ってしまった」から生まれた
4. **過去の回は対象外にする。**古い `report.json` には新しい項目が無い。
   さかのぼって埋めない（推測値を記録に混ぜない）。
   **いつの回から必須になるかを検査に書く**

- **共有ツリーで作業しない。**`git worktree add ../isa-wt-<名前> -b task/<名前> main`
