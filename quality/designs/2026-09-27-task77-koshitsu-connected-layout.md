## 工程1: 内容の接続表

ページ内の `PLANET_DATA` を正典とし、別の件数・投稿・主張一覧を作らない。読書面は論点IDから次の要素を参照する。

| 論点 | 理由内訳 | 資料照合 | 資料にしかない話 | 制度確認 | 年表 |
|---|---:|---|---|---|---|
| 男系vs女系 | 425件 | claim_1 / claim_5 / claim_6 | なし | 女性皇族と女系天皇 | なし |
| 旧宮家養子縁組 | 269件 | claim_2 / claim_3 | 養子の年齢条件・男子出生の重圧 | 養子本人と子孫 | なし |
| 立法手続き・民主主義 | 228件 | なし | 30年ごとの見直し・成立しなかった修正案 | なし | なし |
| その他 | 216件 | なし | なし | なし | なし |
| 愛子さま・皇族の地位 | 199件 | なし | なし | 婚姻後の身分 | なし |
| 女性天皇・女系天皇 | 188件 | claim_4 | なし | 女性皇族と女系天皇 | なし |

共通の心配 `koshitsu-tenpakai-stability` は男系vs女系・旧宮家養子縁組の両方に表示する。年表3件は複数論点にまたがり、一意に割り当てられないため無タグのままにする。日付切替はページ全体の背景欄で行い、推測で論点を増やさない。

## 工程2〜4: 画面差分

| 要件 | 皇室典範候補での実装 |
|---|---|
| V01 読み順 | 現状サマリー → 立場・山 → 論点ボタン → 選択論点の読書面 → 背景・潮目・編集部整理 |
| V02 立場操作 | 5つの立場と「すべて」を同じ `#modes` に配置。PC6列、スマホ2列＋「すべて」全幅 |
| V03 山の大きさ | PC210px、幅450px以下180px。海面下の装飾を隠してからSVGの実描画範囲を測る |
| V04 論点ボタン | PC4列、スマホ2列。件数と説明を保持 |
| V05 選択状態 | 選択中の立場・論点を濃色、山は選択立場の色で濃淡表示 |
| V06 読書面 | 理由内訳、代表投稿、資料照合、制度確認、共通の心配を論点IDで接続 |
| V07 理由別投稿 | 正典に理由と投稿を結ぶIDがないため、理由別投稿は追加せず、論点ごとの代表投稿2件を維持 |
| V08 資料タブ | 「資料を読む」「x投稿で語られない話」「一次資料クイズ・6問」へ統合 |
| V09 旧節 | 通常画面では `#koshitsu-audit` / `#issue-cards` / `#ocean` / `#bukatsu-check` を読書面へ統合して非表示。印刷・JS無効時は本文を保持 |
| V10 見た目 | 既存の青系配色を維持し、山から読書面までの余白・見出し・2段組を参照版に合わせる |
| V11 動き | 山の切替は既存bridgeの480ms遷移。`prefers-reduced-motion` 時は即時反映 |
| V12 保全 | 投票24選択肢、出典、確認日、授業・印刷導線、JS無効時の旧本文を保持 |

## 再生成と保全

- `scripts/koshitsu_connected.py` がページ内データと背景JSONから接続表・読書面を生成する。
- `scripts/refresh_planet_section.py` と `scripts/build_koshitsu_arena.py` の両方で、山なみ更新の最後に同じ処理を再適用する。
- 接続表、読書面テンプレート、bridge、CSS、ページ全体の再配置JSは、同じ入力で再実行しても重複しない。
- 公開HTMLを有効化して本番へ反映した。投票データ・Edge Functionの変更は含めていない。
