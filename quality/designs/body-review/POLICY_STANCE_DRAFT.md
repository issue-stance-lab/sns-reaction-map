# 人物への評価と政策への賛否を分ける基準案 v1

課題63、2026-09-07。状態：検討用の案。現行分類・採用台帳・分類器・公開ページへは未適用。

**投稿者が「何を、どう評価し、どうしてほしいのか」を根拠にする。人物・政党・陣営への好き嫌いから、政策への賛否を補わない。**

「賛成」「反対」の単語がなくても、政策を実施・撤回してほしいという要求や、政策そのものへの明確な評価は判定の根拠にできる。単語の有無だけで保留を増やさない。

## 1. 何が問題だったか

[今回の4,000件集計](../../reviews/2026-09-07-cycle-next2000.md)では、保留1,764件のうち157件を「批判と政策への賛否の区別」という原因候補へ整理した。これは複数テーマにまたがる整理用の集合であり、誤分類157件・この案で解消できる157件を意味しない。他の理由群にも同じ問題が含まれ得る。

保存理由では、改憲反対派への批判から改憲支持を導く、減税公約への不満から減税支持を導く、AI利用への嫌悪から法的規制支持を導く、といった境界が見られた。本案はその境界を説明可能にする。今回行ったのは基準文と保存理由の照合であり、代表投稿の本文再判定や精度検証はまだ行っていない。

## 2. 判定する順番

1. **誰の意見か。** 引用・報道・批判されている相手の発言と、投稿者自身の評価を分ける。引用しただけでは同意としない。
2. **何への評価か。** 人物・政党、議論の態度、政策そのもの、政策の一部、代替案を分ける。
3. **どう評価しているか。** 肯定・否定・条件・実施要求・撤回要求を本文から読む。怒りの強さは賛否の対象を決める根拠にならない。
4. **どこまで言えるか。** 候補地だけ、条項だけ、実施方法だけへの評価を、制度全体への賛否へ広げない。
5. **テーマの正式な分類名へ対応させる。** 主な論点と賛否を別々に選び、根拠となる短い箇所と対象範囲を残す。矛盾や不足が残る場合は保留する。

投稿者の過去の発言、所属陣営、プロフィール、他人の評判から足りない賛否を埋めない。追加文脈を使う場合は、その文脈自体を取得・保存し、元投稿との関係を確認する。

## 3. 賛否を判断できる根拠

| 根拠 | 扱い |
|---|---|
| 本人が政策への賛成・反対を明示 | その対象範囲で判定できる |
| 本人が政策の実施・撤回を要求 | 「賛成」「反対」の語がなくても、その対象範囲で判定できる |
| 本人が政策自体を明確に肯定・否定 | その評価がテーマの立場定義に合えば判定できる |
| 人物や陣営だけを肯定・否定 | 政策への賛否は導かない |
| 政策に関する事実認識だけを訂正 | その政策への支持・反対は導かない |
| 政策の一部や代替案を評価 | 対象を限定して記録。既存ラベルで表せなければ保留 |
| 引用、皮肉、指示語の対象が曖昧 | 必要な文脈を指定して保留 |

「Aに反対する人を批判している」は、Aへの支持の証明にはならない。逆に、Aを推す人への批判もAへの反対の証明にはならない。両陣営に同じ基準を使う。

「この政策は無駄だ、やめてほしい」は政策への反対を読める。一方、「この政策の反対派は嫌いだ」では反対派への評価しか読めない。この違いを基本線とする。

## 4. 「政策への賛否不明」と「判断保留」を分ける案

- **本文が十分で、政策への賛否を述べていないと判断できる場合**：本人の関連する意見は意見として保持し、現行ラベルの「中立・情報」等へ対応する候補にする。人物批判を、ニュース共有や意見なしへ一律に落とさない。
- **本文が欠けている、皮肉・引用の帰属が曖昧、複数の解釈が残る場合**：判断保留。追加で何が必要かを記録する。
- **本文の意味は明確だが、既存ラベルに対応できない場合**：基準・ラベル設計の保留。便宜的に中立へ入れない。

「中立」は賛否がちょうど半々という意味とは限らない。今回の4テーマには立場不明を含むラベルがあるが、他テーマへは定義を確認してから広げる。将来ページへ反映する場合は、「中立」と「政策への立場が読み取れない投稿」の表示上の混同も点検する。

例：消費税の公約に関する本人の批判だけなら、関連性あり・意見あり、論点「公約と政治不信」、政策への賛否は「中立・情報」という候補が考えられる。ただし、文脈の欠落が疑われる投稿はこの理由だけで確定しない。

## 5. テーマごとの境界

| テーマ | 判断できる内容 | 飛躍させない内容 |
|---|---|---|
| AI著作権 | 利用の推進、無断学習の制限、許諾要求など、本人が求める行動 | AI絵への嫌悪・創作性否定・利用者批判だけから規制強化支持を導くこと |
| 憲法改正 | 改憲・特定条項の推進や反対、手続き改善を本人が求めること | 反対派批判から改憲支持、国民投票の実施支持から改憲内容への支持を導くこと |
| 消費税減税 | 減税・廃止・対象拡大を求めること、減税自体への評価 | 公約違反への怒りだけから減税支持、限定案への批判だけから減税全体への反対を導くこと |
| 副首都 | 構想・法案への本人の評価や実施要求 | 維新への評価、特定候補地への評価を法案全体の賛否へ広げること |

AIの「規制・制限強化支持」は制限支持を表すラベルなので、否定的感情だけでは足りない。一方、副首都の「法案反対」は構想への否定的評価を含む。必要な根拠は各テーマのラベル定義に従い、一律に「具体的な法律案まで書かれていなければ保留」とはしない。

## 6. 判定例（説明用の架空例。実投稿の引用ではない）

| 本人の投稿の例 | 本案での読み方 |
|---|---|
| 「あの党は嫌い。でも減税は早く実施してほしい」 | 人物評価と切り離し、減税推進 |
| 「減税を公約にしたのに約束を守らない。信用できない」 | 公約への不信。これだけでは減税への賛否を補わない |
| 「食料品だけでは足りない。全品目を下げてほしい」 | 減税支持と対象拡大要求。条件付き賛成・政府案に不満 |
| 「減税は社会保障を壊すからやめてほしい」 | 減税反対・慎重 |
| 「改憲反対派の言い方が嫌い」 | 議論の態度への批判。改憲支持は不明 |
| 「9条を改正して自衛隊を明記すべき」 | 9条・自衛隊を対象とする改正推進 |
| 「国民投票の広告ルールを公平にしてほしい」 | 手続き重視。改憲内容の賛否は補わない |
| 「AI絵は好きではない」 | 好み・生成物の評価。規制強化支持は不明 |
| 「本人の許諾なしで作品を学習に使うのは禁止すべき」 | 学習利用の制限支持 |
| 「規制派の態度は嫌いだが、無断学習は制限すべき」 | 人物評価と切り離し、制限支持 |
| 「副首都は福岡がよさそう」 | 候補地の提案。現法案全体への賛否は補わない |
| 「副首都構想は税金の無駄だ。やめてほしい」 | 構想そのものへの反対 |
| 「あの政党は支持しないが、この副首都法案は進めてほしい」 | 人物評価と切り離し、法案賛成・推進 |
| 「『減税は不要』という記事を共有します」 | 共有だけでは本人の反対としない |

各例は境界を説明するためのもの。実際には全文・引用関係・基準との版一致を確認し、4項目すべてを判定する。

## 7. 現行基準との差と採用前の確認

今回の確認に使った基準は、保存パケットが指す以下の分類器内の文章。旧設定のラベルと混ぜない。

- `scripts/classify_aicopyright_arena_hermes.py`
- `scripts/classify_constitutional_arena_hermes.py`
- `scripts/classify_consumption_tax_arena_hermes.py`
- `scripts/classify_fukushuto_arena_hermes.py`

いずれも引用と本人の主張の区別を求めている。本案では、人物評価からの飛躍禁止、政策自体の評価を根拠にできる範囲、賛否不明と保留の区別を明文化する。特に「賛否不明として中立候補へ進める」境界は、従来の保留を変え得るため試験が必要。

`configs/topics/ai-copyright-v2.yaml` は感情や評価からの分類と広い否定ラベルを許容し、今回のAI分類器の制限支持ラベルとは同じ意味ではない。`configs/topics/fukushuto.yaml` も感情からの判定を許容する。設定と分類器のどちらかを黙って上書きせず、採用時は実行経路ごとの参照基準・ラベルを整理する。原本や過去の判断は新しい基準で上書きせず、基準の版と変更理由を持つ別の再判定記録を作る。

## 8. 次に行う限定試験

対象は20件。AI・改憲・減税・副首都から各5件を、保存理由と本文を照合して選ぶ。各テーマで「人物評価だけ」「政策への明確な評価・要求」「条件・対象範囲」「引用や文脈不足」の境界を含め、既存採用例も比較対象へ入れる。難例を選ぶ試験なので全体精度の推定には使わない。

1. 対象ID・本文・元判断・現行基準・本案の版を固定する。対象選択は自動でも、本文判断は個別に行う。
2. 編集担当と独立担当が相手の判定を見る前に、発言者／評価対象／要求・評価／対象範囲／根拠／4項目の候補／不確実性を保存する。
3. 旧基準と本案で何が変わるか、根拠が足りるかを比較する。不一致は多数決で消さず、原因を記録する。
4. 結果を「再判定候補に進める」「文脈が必要」「ラベル設計が必要」に分ける。判定の一致数だけで本案の妥当性を決めない。
5. 本人の根拠を示せない賛否推定、意見の一律除外、対象範囲の拡張があれば案を修正する。解消しない境界は保留のまま残す。

この20件の点検後に、具体的な変更候補と影響をまとめる。現時点の採用2,214・保留1,764・根拠等22件は変更しない。新しい本文確認件数にも加算しない。
