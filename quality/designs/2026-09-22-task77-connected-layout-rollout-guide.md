# 課題77 — 消費税の修正記録と別テーマへの適用手順

記録日: 2026-09-22。改訂: 2026-09-23。消費税減税は9/22に承認・公開済み。
部活テーマで、機能を接続しても消費税と画面構成が異なる結果になったとの指摘を受け、見た目の実装範囲と工程ごとの合格条件を必須項目へ改訂した。
この文書を、別テーマで同じ表示を作るときの入口にする。対象の `themes/{テーマ名}.md` と生成元を読み、工程1で**内容の接続表と画面の差分表の両方**を作る。
公開時点の実物は[消費税減税のページ](https://sns-reaction-map.jp/consumption-tax-cut-reaction-map.html#modes)、配信・検証の証拠は[公開記録](../reviews/2026-09-22-task77-tax-publication.md)。

## 移植の必須範囲と「維持する」の意味（2026-09-23改訂）

**「消費税と同じ作業」「連動表示の移植」には、ページ全体の配置・見た目・操作体験を消費税の完成版に合わせて組み直す作業を含む。**
データの接続や論点パネルの差し替えだけでは完了しない。山の実表示サイズ、ボタンの並べ方、余白、表示順、旧セクションの統合・折りたたみまで対象にする。

- **「維持する」=情報・出典・確認日・ID・既存機能・到達可能性を保つこと。** 旧位置・旧サイズ・旧カードをそのまま表示し続けるという意味ではない。各節の移設先を下の対応表で指定する。
- **「消費税を参照」=公開画面を操作し、HTML・CSS・描画JS・ページ全体の配置処理を読むこと。** データ構造リファレンスだけで代用しない。CSSは「実装を読む順序」の配置と色、JSは山と閲覧状態・資料タブとページ全体の行を必読とする。
- **個別テーマの計画には、下の工程別完了条件とV01〜V12を転記して具体化する。** 元資料へのリンクだけ、または過去の消費税・部活工程表のコピーだけで計画完成としない。
- 対象テーマの事実・件数・論点名・資料数・確認日はそのテーマのものを使う。長いラベル等への調整は、理由と比較画像を差分表へ残す。文章や件数が異なるための高さの差と、設計を再現していない差を区別する。
- 必須機能を作業量だけを理由に範囲外へ移さない。元の依頼で認められた変更があれば根拠を記録する。原材料の欠如は出所を確認して「該当なし」または未完了とし、架空の理由・投稿・資料で埋めない。
- **機能検査の合格と見た目の合格を別々に記録する。** 自動テストが通る、横にはみ出さない、公開済みである、という事実だけで外観の再現を合格にしない。

今回の改訂は今後の移植仕様を明確にするもの。部活版の既存の公開・検査記録は当時の実施履歴として残し、この改訂だけで画面の差を修正済みとは扱わない。

## 今回、何を変えたか

目的は、既存の情報をつなぎ、読みたい内容を選びながら読めるようにすること。冒頭の質問は増やさず、既存のバー・予想問題を再利用した。

| 部分 | 公開した最終仕様 | 別テーマでも引き継ぐこと |
|---|---|---|
| 「意見は、どこで分かれている？」 | 立場バー→5つの立場ボタン→山→7論点ボタンを一続きに配置。重複していた立場操作を1組に集約 | 操作した場所と変化する場所を近づける。ボタン数は対象テーマから取得する |
| 選択の見分け | 選択ボタンはクリック直後に濃紺・白文字。山は選んだ立場の色でそろえ、選択中を濃く、他を薄くする | 色・押下状態・件数を同時に変える。見本の紫へサイト全体の色を変えない |
| 山の動き | 480msで変形。すぐ動き始め、最後にゆっくり止まる。論点の並びと0〜100%の軸は固定 | 選択時に山や画面が移動しない。連打は最後の選択へ収束。動きを減らす設定では即時切替 |
| 論点本文 | 選んだ論点の理由・投稿・制度・資料を同じ場所へ表示。PCは左右、スマホは上下 | 理由の上位項目と詳細の開閉を組み合わせる。未再読・資料なし・意見0件を区別する |
| 「どんな理由で語られる？」 | 再読済み25理由を開くと、各理由に属するX投稿の要旨・元リンク・公式カードを表示。既存の論点別14投稿も維持 | 理由IDと投稿IDを照合する。Xの読み込みに失敗しても要旨とリンクを残し、開き直しで再試行できるようにする |
| 資料の入口 | 「資料を読む」→「x投稿で語られない話」→「一次資料クイズ · 6問」の順。中央タブに資料側の4項目を集約 | 元の「資料にあり、収集投稿で見つからなかったこと」は論点本文に残す。中央タブはテーマ全体の入口として追加する |
| ページ全体 | 年表・収集比較・進捗・戻る/進む・論点リンク・引用・授業・印刷・投票を接続 | 現行ページの機能を先に一覧化し、移動後も到達できることを確かめる |

**集計の範囲を混ぜない。** バー・山・選択論点の件数は立場で絞る。理由分類・投稿例・資料は論点全体の内容として表示し、その旨を明記する。
理由別の投稿例は「選んだ立場の代表」とは限らない。立場別表示にするなら、別途その分類と本文の確認が必要になる。
「x投稿で語られない」は収集した投稿の範囲で見つからなかったという意味。X全体に存在しないとは書かない。

消費税では山の高さをPC210px・狭い画面180px、選択時の不透明度を0.9・非選択を0.23にした。
0件の山は描かずボタンと資料を残し、強い表現0%は基準線上の点で示す。小さい山の最小幅補正は注記し、正確な件数をボタンに出す。
これらは公開版の比較基準。別テーマの長いラベル・論点数でも読めるかを確認して適用する。

合わせて直した原稿は、予想Q1の差（推進1834件−慎重1035件＝799件）、Q2の件数と割合の混同（対象範囲885件中、強い表現464件・52.4%）、
古い集計値が残る観察記録、事業者の負担を全論点で最少とする表現（112件・2.9%という量へ変更）。いずれも当時の元データへ同期した訂正で、
他テーマへ文章や数値を流用する対象ではない。詳しい理由と処置は `correction-20260922-001` と[公開記録](../reviews/2026-09-22-task77-tax-publication.md)に残した。

## そのまま使える考え方と、テーマごとに確定するもの

**現状の実装は消費税専用。テーマ名を置換するだけでは適用できない。** `consumption_tax_connected.py` は対象を限定し、他テーマには何もしない。
次のテーマで差分を調べ、同じ処理だけを共通化する。共通化は今回済ませていないため、既存テーマへ一括で有効化しない。

| 共通して使える設計 | テーマごとに確定する内容 |
|---|---|
| 閲覧中の立場・論点を1か所で持ち、バー・山・本文を同期 | 論点ID、立場ID、色、表示順、初期論点。消費税の「対象範囲」を他テーマへ固定しない |
| IDで理由・投稿・資料を結び、表示名や順位から対応を推測しない | 再読状態、理由IDと投稿の所属、要旨・URLの生成元、資料の関連論点 |
| 元の本文・集計から生成し、同じ入力で同じ結果になる仕上げ処理 | ページ生成器、部分更新、潮目、編集情報、授業節の実際の更新経路 |
| 元の資料欄と横断タブで同じ本文・出典・読了IDを使用 | 制度・照合・資料側項目・共通する心配・年表・図解の有無と確認日 |
| 投票の選択を閲覧と分け、公開済みの保存番号を維持 | 投票のtopic、論点/立場ID→固定番号、保存キー、過去データとの互換性 |
| 質問・クイズ・資料の数を元データから取得 | 7論点・4立場・25理由・14投稿・4項目・6問・投票28通りは消費税の実績値。別テーマに持ち込まない |

資料や再読記録が不足する箇所は、不足として接続表へ書く。空欄を埋めるための制度説明・理由・質問・投稿日を作らない。
見た目の変更日、データ収集日、制度の確認日、資料照合日、理由の読了日は別々に扱う。

### 旧セクションの処置を決める表

対象テーマの全セクションを列挙し、下の例を起点に**「旧要素→処置→新しい表示先→出典/リンクの保持方法」**を埋める。「維持」とだけ書いた行は未確定。
消費税にない節も必ず追加し、そのまま表示するなら読み順の理由を記録する。要素IDが同じでも、内容が同じと推測しない。

| 旧要素の例 | 消費税を基準にした処置 | 保持を確認するもの |
|---|---|---|
| 立場バー、重複した立場フィルター | 山の直前へ移動・1組へ集約 | 選択肢・件数・色・閲覧状態 |
| 長い背景説明・`#bukatsu-background` | 現状の短文を冒頭へ。背景の詳細は折りたたみ、年表は山と読書面の後へ移動して日付で切替 | 全日付・本文・出典・確認日 |
| 制度の独立カード・`#bukatsu-check` | 関連論点の資料欄へ統合し、統合済みの旧カードは通常画面で非表示 | 全項目と関連先・出典。対応が未確定なら黙って隠さない |
| 資料照合一覧・`#claim-audit` | 論点の資料欄へ統合し、旧一覧は通常画面で非表示 | 全主張・照合内容・対象範囲・根拠リンク・確認日 |
| 論点別X投稿一覧・`#issue-cards` | 該当論点の読書面へ統合し、旧一覧は通常画面で非表示 | 既存の選定投稿・要旨・URL、旧論点リンクからの到達 |
| 旧海面下パネル・`#ocean` | 共通の心配・資料側項目を関連論点へ統合。資料側項目の横断入口も追加し、旧全体パネルは通常画面で非表示 | 論点内の資料側項目は残す。横断タブと同じ本文・出典・読了IDを使う |
| 独立した一次資料クイズ・`#quiz` | 資料欄のクイズタブへ移動 | 全問題・根拠・回答状態・論点への接続 |
| 編集部の横断整理・`#editorial`、図の見かた・`#meta` | 後段で折りたたみ、必要時に全文を読めるようにする | 全本文・出典。編集・分析情報など別の節と取り違えない |
| 調査条件、投稿比較、投票、授業、編集・分析情報、訂正窓口、関連テーマ | 各節の表示先・順序を個別に指定し、既存機能を接続 | 期間・母数・注意書き、保存番号、引用/授業/訂正リンク、計測 |
| 静的本文・`#fallback`、印刷用本文、保護タグ | JavaScript無効・初期化失敗・印刷時の読める本文を維持。GA4/AdSense/Supabase/canonical/OGPも保持 | 通常画面向けの非表示処理が、代替本文や印刷まで消していないこと |

### 工程5で残す比較証拠と工程6への条件

1. 消費税の参照版と候補版について、URL・確認日時・コミットまたはHTML/JS/CSSの識別値を記録する。制作途中の旧アーティファクトを最終仕様として使わない。
2. Chromium・WebKitで1280/375/320pxを確認。両ページを**同じ幅・文字倍率・動き設定**にし、初期状態、立場選択後、論点選択後、理由展開、資料3タブ、後段の全ページを対応づけて撮影する。
3. テーマ間で論点名・件数は違うので、資料が多い／未再読／少件数など同じ役割の論点を選ぶ。0件等の機能試験は各テーマの全組合せで別に行う。
4. 比較画像を横に並べてV01〜V12を確認し、山の実寸・ボタン列数・節の順序・旧節の可視状態は数値やDOMの確認も添える。静止画に加え、選択直後と変形途中の記録を残す。
5. 各行に「判定／画像や検査ログ／差がある理由／修正する工程」を書く。**未達・未確認は工程3または4へ戻す。外観確認を省いたまま工程5を完了にしない。**
6. 工程6へ進めるのは、機能・外観の両表が合格し、該当なしや仕様差に根拠がある候補だけ。新たに必須項目を省く必要が生じた場合は、具体的な代替案と影響を提示し、元の依頼範囲を勝手に狭めない。

## 確認項目と、今回わかった注意点

- **動きも比較する。** 静止画だけで合否を決めない。立場を押した直後、変形の途中、停止後を見て、選択が即座に伝わるか確認する。初期見本との比較は[選択動作の修正記録](../reviews/2026-09-22-task77-tax-selection-motion.md)。
- **全組合せを対象データから数える。** 消費税は7論点×5表示＝35通り。0件、全件0、同率、強い表現0/100%、順位変更も確認する。数字・色・押下状態・説明の食い違いを調べる。
- **PCとスマホ幅。** Chromium・WebKitの1280/375/320pxを基準に、長いラベル・右端の山・出典リンク・Xカードを確認する。横スクロールの有無だけでは、文字の見切れを見逃す。
- **連打と画面幅変更を同時に試す。** 消費税ではWebKitの変形中の拡幅でResizeObserverの循環通知を検出し、次フレームで描画する修正を行った。連続20回の切替中に拡縮して再確認した。
- **読めない時の入口を残す。** JavaScript無効・初期化失敗、X読込の遅延/失敗/再試行、資料なし・未再読でも元本文と必要なリンクへ到達できるか確認する。
- **投稿の内容を照合する。** 全理由について投稿本文・所属・要旨・URLを確認する。消費税は監査で文脈や個人への侮辱が問題となる6例を差し替えた。件数やURLの一致だけで代表性を判断しない。
- **資料3タブを往復する。** 元の論点別資料、横断項目の本文・出典・調査範囲・確認日、クイズの回答、進捗の重複防止を確認する。資料がないテーマへ架空のタブ内容やクイズを足さない。
- **通常更新を通す。** 全体生成だけでなく部分更新→潮目→編集情報→授業節を連続適用し、もう1回実行しても旧配置・古い数字・重複した操作が戻らないことを確かめる。
- **既存機能を守る。** 投票の全固定番号と既存保存形式、引用・内部リンク、戻る/進む、進捗、授業用A4・全論点印刷、GA4/AdSense/Supabase/OGPを確認する。投票送信はテスト応答で確認する。
- **計測に選択した意見を入れない。** 消費税の `reason_post_open` / `source_only_tab_open` はテーマIDのみ。理由名・立場・投稿URLをイベントへ付けない。中央タブを開いた人数を資料本文の読了人数と扱わない。
- **古い候補で新しいデータを上書きしない。** 公開直前に正典・本文が更新されていれば最新の生成元から作り直す。HTML・JS・CSSを同じ候補として固定し、公開対象と配信結果を照合する。

公開前の全体検査、承認後のマージ・push、2本の配信関連検査、実URL確認、バックアップ・作業ツリー整理は[release手順](../../.claude/skills/release/SKILL.md)を使う。
実スマホ端末・製品版Safari・紙への印刷は、ブラウザーエンジンやPDFの検査と区別して記録する。
