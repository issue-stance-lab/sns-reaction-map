# 課題54 段階8: 「同じ数字は1回だけ」を検査にする（2026-09-05）

`verify_theme_page.py` に `verify_one_number_per_page()` を足し、
論点数・意見数・収集数が1ページの中で2通り出ていたら止まるようにした。
作業ツリーは `task/task54-stage8-one-number`。

## 何が起きていたか

自転車ページは同じ画面に「5つの論点」と「6つの論点」が同時に載っていたのに、
既存の検査は両方 `OK` と判定していた。手順書に「同じ数字は1ページに1回だけ」と
書いてあっても、検査が無いので守られなかった。

検査を入れたところ、**11テーマ中5テーマで6件**見つかった。すべて実在の食い違いだった。

| テーマ | 何が食い違っていたか | 直し方 |
|---|---|---|
| 自転車 | 「5つの論点」と「6つの論点とXの声」（並んでいるのは論点1〜5の5つ） | 見出しを5へ |
| 自転車 | マップ説明が「6つの論点セクター」（実際は5論点＋その他の6区分） | 「5つの論点と「その他」のセクター」へ |
| 部活動 | マップ説明だけ「6つの論点セクター」（マップは7区分を描き、他は7で通っている） | 説明を7へ |
| 消費税 | マップ説明だけ「7つの論点セクター」（他は6で通っている） | 「6つの論点と「その他」のセクター」へ |
| あだ名禁止 | 本文に「意見87件」が残っていた（現在の母数は93件） | `configs/theme-seo.json` を93へ直し、`apply_theme_trust.py` で反映 |
| 高市 | タイル「分析対象の意見621件」とリード「分析対象となった意見620件」 | 621は意見と判定した数、620は5論点に整理した数。タイルの見出しを「意見と判定した投稿」へ |

**直す前に、その数字が何を指しているかを実物で確かめた。** マップの区分数は
埋め込みデータの `i:` 番号から数え、セクションの論点数は見出しを数えた。
どちらの数が正しいかはテーマごとに違い、リード文の数は `sync_issue_counts.py` が
正典から書き込むので、そこを手で変えると次の更新で戻る（部活動で一度踏んだ）。

## 検査の作り

`scripts/verify_theme_page.py` の `verify_one_number_per_page()`。

- **論点数**: 「Nつの論点」「N論点」を拾う。ページの中で2通り以上あれば**不合格**
- **意見数・収集数**: 拾った値を公開データ契約（`data/public/themes/`）と突き合わせ、
  違う値が書かれていれば**不合格**。未公開テーマは正典が無いので、ページ内で
  食い違わないことだけを見る

**騒がせないために外したもの**（どれも実際に誤検知した）:

1. **他テーマの紹介文**。「関連テーマ」の中の「憲法改正…をめぐる6論点」は
   このページの数ではない。`related-section` / `related-grid` を対象外にした
2. **論点ごとの内訳**。「意見103件のうち100件が…」は部分集合。
   直後が「のうち」「の内」「中で」なら数えない
3. **過去の版を述べた文**。「2026年8月8日に…意見765件から作り直しました」は履歴。
   ただし判定は**同じ文の中だけ**にした。前後を広く見ると、更新履歴の近くにある
   古い数字（あだ名禁止の87件）まで黙って見逃す
4. **順番のラベル**。「論点1」「論点2」は数ではない

## 不合格にしなかったもの（知らせるだけ）

部活動と高齢者免許返納は、ページの中では食い違っていないが、「その他」を論点に
数えている（ページ7・catalog 6／ページ6・catalog 5）。トップページと catalog は
`named_issue_count`（「その他」を除く）を使うので、**サイト全体では数が2通りになる**。

ページの作り直し（段階10）でそろえる。いまページ側を変えると、リード文の論点数と
意見数の対応（`sync_issue_counts.py`）まで作り直しになるため、ここでは知らせるだけにした。

## 検査に足したこと

`tests/test_one_number_per_page.py`（9件）。自転車の食い違いを検出できること、
上の1〜4で騒がないこと、公開中の全ページが通ることを固定した。
