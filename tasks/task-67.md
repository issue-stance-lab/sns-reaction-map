# 課題67: 定期計測が「通常ポスト」を拾わず、URL付き投稿が毎回測り漏れる

**登録日**: 2026-09-12
**状態**: 未着手

## 何が起きたか

2026-09-10 22:00 に出した方式A（本文とURLを1本にまとめた通常ポスト、今週の検証「URLの有無」の比較用）が、
24時間を過ぎても `python3 scripts/x_post_views.py pending --json` に一度も上がらなかった。
そのため 2026-09-11 20:05 の定期計測（`x-daily-measure`）でも測られず、
2026-09-12 08:34 に X運用セッションが手動で計測した（31表示・約34.5時間後）。
気づかなければ、今週の検証は判定材料が片方欠けたまま週次レビューを迎えていた。

## 原因

`scripts/x_post_views.py` の `find_pending()` は、`content/x/posts.md` の `## ○○実績 YYYY-MM-DD` 見出しのうち、
次の3つしか対象にしていない。

- `リプライ実績`（表の「自リプライ表示」列）
- `論点ポスト実績`（`投稿URL:` 行と `表示回数:` 行）
- `### 会話フォロー`

`通常ポスト実績` は、`論点ポスト実績` と同じ `投稿URL:` + `表示回数:` の形で書いていても、見出しの名前が違うだけで対象外になる。

一方、管理ダッシュボード（`scripts/admin_dashboard/collect.py`）は「箇条書き形式（論点ポスト・通常ポスト）」として通常ポストの表示回数を読んでいる。
**表示する側は通常ポストを知っているのに、計測待ちを出す側だけが知らない**、というずれ。

## 影響範囲（2026-09-12 時点の `content/x/posts.md`）

| 見出しの種類 | 節の数 | `pending` の対象か |
|---|---|---|
| リプライ実績 | 66 | 対象 |
| 論点ポスト実績 | 21 | 対象 |
| 通常ポスト実績 | 6 | **対象外** |
| 流入投稿実績 | 3 | **対象外** |
| 引用RT実績 / 引用リポスト実績 | 3 | 対象外 |
| URL付き告知ポスト実績 / 固定ポスト差し替え実績 | 2 | 対象外 |

- 通常ポスト6節のうち、`表示回数:` 行を持つのは 2026-09-10 の方式Aだけ。
  09-04・09-01・08-29 は `計測:` 行の旧形式で記録済み、08-01・07-15 は `投稿URL:` 行も無い古い形式。
  **直すときに古い節まで計測待ちに出さないこと**（すでに測り終えている）
- URL付き流入投稿は週1〜2本出す運用なので、放置すると**毎週1〜2本ずつ測り漏れる**

## 直し方の案

1. `find_pending()` の `論点ポスト実績` の分岐を、`通常ポスト実績` と `流入投稿実績` にも適用する
   （`投稿URL:` 行と `表示回数:` 行が両方ある節だけを対象にする。旧形式は `表示回数:` 行が無いので自然に外れる）
2. `PendingPost.kind` に見出しに応じた名前（`通常ポスト` など）を入れる
3. `apply_measurements()` が同じ節の `表示回数:` 行を書き換えられることを確認する
4. `tests/test_x_post_views.py` に、未計測の `通常ポスト実績` が `pending` に出ることと、
   `表示回数:` 行の無い旧形式が出ないことのテストを足す

## 完了条件

- 上記テストが通る
- 次にURL付き通常ポストを出したとき、24時間後の定期計測で自動的に測られる（手動計測が要らない）

## 注意

- 定期計測（毎日20:05）は別セッションで走っている。直した版が main に入る前後で、同じ投稿を二重に測らないよう、
  手動計測済みの節（2026-09-10 方式A）は `表示回数:` が埋まっていることを確認してから反映する
- リプライ実績表の8列は変えない（`OPERATIONS.md` の測定欄の注意、`scripts/admin_dashboard/collect.py` が列名に依存）
- 投稿の書式を直す方向（通常ポストを `論点ポスト実績` と書く）では解決しない。見出しは投稿の種類の記録でもある
