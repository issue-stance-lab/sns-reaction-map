**目的**: テーマごとに雑多な情報を縦に並べるページから、読者が議論の全体像を回し、論点へ着陸し、

**照合レイヤー（2026-09-01 追加）**: 惑星の陸地は「SNSで何が語られたか」で、これは収集と分類の仕組みが
あれば再現できる。独自性はそこには無い。海面より下に、**人が一次資料を読まないと出てこない情報**だけを置く。

- **沈んだ大陸** — 一次資料では争点なのに、収集した投稿にほとんど無い論点

「無いもの」は集計できない。人が資料を読んで初めて分かる。この非対称が「AIが集めて分類しただけ」を
構造的に成立させなくする。仕様は設計書 3.3、書き方の基準は 3.3.2（重要度の名指しはしない）。

**変えない意味**:
- 球体全体 = 1テーマ
- 大陸・島 = 論点
- 面積 = その論点に分類された意見数
- 色 = その論点内のスタンス分布（テーマ固有ラベルを使い、単純な赤青へ固定しない）
- 標高 = AI分類から再現可能な「強い表現の割合」。正しさ・重要度・世論の熱量とは呼ばない
- 大陸の位置 = 初版では見やすさのための配置。論点同士の近さを意味しない

### 再発防止規約（消費税減税から得た教訓）

以下の規約を「編集再読」作業の標準手順として遵守する。

1. **物理的上限の計算**: 1件ずつ読む作業は1件あたり20〜30秒が現実的。
   subagentの600秒制限では20〜30件が上限。それを超える場合は分割投入または人間作業への委譲を検討する。
2. **subagentに「自動分類スクリプトを書かせない」**: 「1件ずつ読んで分類せよ」と指示しても、
   件数が多すぎると自動分類に置き換えられる。カウント可能な件数を守るか、ロックステップで読んだ件数を定期的に報告させる。
3. **完了確認は「数値」だけでなく「中身」も確認する**: 件数・重複・sha256は
   形式的検査であり、要約の品質やバケット割り当ての適切性は検査できない。
   必ず10件以上のサンプルを人間が読んで、「本文と要約が一致しているか」を確認する。
4. **「不可能」と言う、が使える**: 件数が多すぎて物理的に無理な場合、
   「この状況ではできません」と報告し、代替案（分割、人間作業、機械分類で済ませる場合は「未読」明記）を提示する。
   「できないことをできたことにしない」。
